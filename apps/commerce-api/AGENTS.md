# Commerce API 작업 지침

저장소 루트의 `AGENTS.md`에 있는 과제 협업·작업 승인 원칙을 함께 따른다.

## 실습 작업 원칙

- 합의한 계약·기대값·패키지 의존을 따른다. 미정 정책은 먼저 질문한다.
- 이번 기능에서 변경할 책임·파일·관련 테스트를 먼저 제안한다.
- 작은 기능을 구현하고 diff와 관련 테스트·lint(Checkstyle)·ArchUnit 결과를 확인한다.
- 검사를 통과시키기 위한 테스트·기대값·규칙 삭제나 완화는 하지 않는다.
- 승인된 요구사항 변경으로 효력을 잃은 테스트는 근거와 대체 검증을 기록하고 제거·교체할 수 있다. 여전히 유효한 기존 기능의 검증은 유지한다.
- 정책·검사 기준 변경이나 범위 밖 개편은 이유와 영향을 설명하고 확인을 받는다.

## 이 프로젝트의 적용 기준

- `docs/system-design/system-design.md`를 API 구현의 기준으로 사용한다.
- 문서에 `[잠정]`으로 표시된 정책은 미정 정책으로 다시 질문하지 않고, 적힌 현재 값을 기준으로 구현하고 테스트한다. 기획 결정에 따라 변경될 수 있으므로 잠정 표시를 임의로 제거하거나 확정 정책으로 해석하지 않는다.
- 문서에 없는 기능이나 운영 정책을 임의로 추가하지 않는다. 외부 동작에 영향을 주지 않는 내부 구현은 문서의 구조와 의존성 원칙 안에서 결정한다.
- 승인된 작업 단위 안의 관련 수정·검증은 별도 승인을 반복해서 요청하지 않는다. 다음 작업 단위를 시작하기 전에는 사용자의 승인을 받는다.
- 구현 과정에서 합의된 계약이나 설계 판단이 변경되면 관련 코드와 테스트뿐 아니라 설계 문서도 함께 수정한다.
