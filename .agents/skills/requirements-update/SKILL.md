# 요구사항 갱신

요구사항 문서는 기존 항목을 수정하지 않고 **항목 추가와 삭제만** 허용한다.

1. 새 요구가 기존 항목과 양립하면 새 ID로 추가한다. 기존 ID·문장·출처·결정·근거를 수정하거나 번호를 재사용하지 않는다.
2. 기존 항목이 더 이상 유효하지 않으면 그 항목을 삭제하고, 대체 요구를 새 ID로 추가한다. 기존 문장을 새 의미로 덮어쓰지 않는다.
3. 요구사항을 추가·삭제하면 `docs`에서 영향받는 문서를 용어집(`glossary.md`) → 도메인 규칙(`domain-rules.yaml`) → 도메인 관계(`domain-relations.md`) → API 계약(`api-contract.md`) → 시퀀스 다이어그램(`representative-flows.md`) 순으로 수정한다.
4. 이후 저장소의 모든 문서·코드·테스트에서 삭제한 ID와 변경된 동작을 검색하고, 영향받는 곳을 수정한다. 과거 기록의 ID를 새 요구사항 ID로 바꿔 쓰지는 않는다.
