# ADR 0010: 사용자 잔액을 먼저 잠그고 지급 기록을 최신 조회한다

Status: Accepted
Date: 2026-10-09

## Context

잔액 숫자와 지급건별 사용·만료 내역을 함께 보호해야 한다. 비교 과정과 예시는 [설계 2.4](../week3/design.md#24-포인트-결제충전만료)에 남긴다.

## Decision

사용자 잔액 행을 먼저 잠그고, 지급건과 사용 기록도 별도의 잠금 조회로 읽는다. 기존 `PointBalance`의 만료 정리·지급건 선택 행동을 유지하며, 이전 REPEATABLE READ 스냅샷을 읽지 않기 위한 선택이다. 결제·충전·조회·배치가 같은 경로를 사용한다.

## Alternatives and costs

조건부 UPDATE도 가능하지만 잔액 차감만으로 지급건 선택은 보호되지 않아 내역 조회 순서와 JPA 상태 동기화가 추가로 필요하다. 대표 버전의 낙관적 락도 가능하나 충돌 시 주문 전체 롤백과 이후 응답·재시도 정책이 필요하다. 자동 재시도는 필수가 아니다. 선택한 방식은 지급건 판단 전에 순서를 정하기 쉬운 대신 기다림과 잠금 유지 시간의 비용을 부담한다.

## Consequences

첫 포인트 조회부터 잠금 경로를 사용한다. 이미 일반 조회한 관리 객체를 잠금 조회만으로 갱신한다고 가정하지 않는다. 두 List를 한꺼번에 fetch하지 않으며, 부모 외래 키는 INSERT부터 저장되도록 매핑한다. 기존 DB의 스키마·누락 계정 이관은 별도 확인이 필요하다.

전체 지급건·사용 기록 조회는 현재 모델의 비용이며, 낙관적 락으로 전환해도 자동으로 없어지지 않는다. 이력 증가에 따른 처리 시간과 반복 조회 비용은 미측정이다. 주문이 이미 잡은 상품 잠금과 공통 커넥션 풀을 통해 다른 사용자에게도 영향을 줄 수 있다. 조회 비용과 잠금·연결 대기를 관찰한 뒤 조회 범위 또는 보호 방식을 재검토한다.

검증 결과와 관찰된 한계는 [구현 기록 2.4](../week3/implementation-log.md#24-포인트-결제충전만료)에 둔다.
