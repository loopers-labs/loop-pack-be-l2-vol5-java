# ADR 0022: 상품 목록은 총상품수 없이 반환한다

Status: Accepted
Date: 2026-10-16

## 이유와 결정

상품 목록은 인덱스 실험과 같은 상품 페이지·그 상품들의 좋아요 수를 제공한다. 사용자가 총상품수는 필요하지 않다고 명시했으므로 총상품수를 구하는 비용을 포함하지 않는다.

- 공통 상품 목록 응답은 `items`, `page`, `size`를 반환한다. 다른 정렬도 같은 응답 DTO를 사용한다.
- 가격순은 기존 필터·삭제 제외·가격 ASC/생성 시각 DESC/ID DESC·LIMIT/OFFSET을 유지한다. 총상품수를 위한 SQL은 실행하지 않는다.
- 상품 20개를 고른 뒤 해당 상품 ID의 좋아요 수를 별도 조회해 합친다. 좋아요순은 전체 후보의 좋아요 수로 정렬한 뒤 페이지를 선택하는 의미를 유지한다.
- 캐시에는 상품 ID·이름·가격·생성 시각의 페이지 목록만 저장한다. 기본 prefix는 `commerce:price-page:v3`다.
- 캐시의 기본 흐름·commit 후 DEL·TTL·삭제 보호·실패 정책은 ADR 0021을 따른다.

## 영향과 검증

클라이언트는 전체 상품 수나 총 페이지 수를 응답에서 얻을 수 없다. 빈 페이지는 빈 items로 반환하며 page·size와 입력 검증은 유지한다. 이를 대신하는 hasNext·추가 한 행 조회·커서 계약은 도입하지 않는다.

캐시 없음/로컬/Redis miss·hit은 동일한 인덱스·데이터·요청·응답 범위로 비교한다. 총상품수 COUNT를 포함한 측정값을 이 조회의 근거로 사용하지 않는다.

정상 조회·정렬·페이지·삭제/오류와 캐시 갱신·rollback·늦은 채움·실제 Redis 장애를 관련 테스트로 다시 확인한다. 실행 결과와 제한은 [4주차 구현 기록](../week4/implementation-log.md#price-cache-without-count)에 기록한다.
