# ADR 0017: 좋아요 중복은 유니크 제약으로 판단하고 취소는 조건 삭제한다

Status: Accepted
Date: 2026-10-09

## Context

같은 좋아요 관계의 동시 등록·취소에서 기존 순차 요청의 응답 계약이 깨졌다. 문제를 발견한 과정은 [설계 3.1](../week3/design.md#31-좋아요-관계의-동시성-범위)에 남긴다.

## Decision

등록은 INSERT 후 `uk_product_like_user_product` 충돌만 중복으로 처리하고, 취소는 사용자·상품 조건의 DELETE로 처리한다. 최초 201·중복 200·취소 204를 유지한다. 별도 카운터나 상품 단위 잠금은 추가하지 않는다.

## Alternatives and costs

선조회는 등록·삭제 사이의 경쟁을 막지 못한다. 상품 잠금은 다른 사용자의 관계까지 기다리게 한다. INSERT IGNORE처럼 다른 입력 오류까지 무시하지 않고 특정 제약 충돌만 처리한다. JPA 저장 예외를 삼켜 롤백 전용 트랜잭션을 계속 사용하는 대신, JDBC 문장을 기존 트랜잭션 안에서 실행한다.

JPA 조회와 JDBC 쓰기가 혼재하므로 동일 트랜잭션에서 미리 적재한 Like 엔티티를 수정·재저장하지 않는다. 현재 쓰기 경로는 관계 엔티티를 먼저 읽지 않는다. 다른 데이터 오류와 잠금 실패는 그대로 전파한다.

등록·취소 경쟁은 DB 처리 순서의 결과를 허용한다. 상품 삭제와 겹쳐 남은 관계는 숨기되 본인 취소는 허용한다. 삭제 완료 후 새 등록은 404로 거절한다. 삭제 상품의 관계가 남아도 노출·구매에는 사용되지 않으므로 이를 막기 위한 상품 잠금은 추가하지 않는다.
