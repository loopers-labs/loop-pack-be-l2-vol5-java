# ADR 0018: 잠금 실패는 503으로 응답하고 자동 재시도하지 않는다

Status: Accepted
Date: 2026-10-09

## Context

기존에는 잠금 실패도 일반 저장 오류와 함께 500이었다. 업무 조건 위반과 잠금 경쟁으로 완료하지 못한 요청을 구분하기로 합의했다. 판단은 [설계 3.2](../week3/design.md#32-전체-잠금-순서와-대기-실패)에 남긴다.

## Decision

Spring의 `PessimisticLockingFailureException` 계열은 트랜잭션 밖 HTTP 경계에서 503으로 매핑한다. 자동 재시도하지 않으며 서비스 연결에서 DB 잠금 대기 시간을 덮어쓰지 않는다. 대기 한도 결정은 측정 후 진행한다([후속 검증](../week3/implementation-log.md#33-커넥션-풀과-성능의-확인-범위)). 다른 저장 오류는 기존 500, 업무 거절은 기존 계약을 유지한다.

## Alternatives and costs

일괄 500도 가능하지만 일시적인 잠금 실패를 구분하기 어렵다. 자동 재시도는 새 트랜잭션과 횟수·시간 한도가 필요하므로 추가하지 않는다. 503이 모든 실패의 자동 재시도 안전성을 보장하는 것은 아니며, commit 결과가 불확실한 오류는 별도로 봐야 한다.
