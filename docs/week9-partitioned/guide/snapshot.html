실행 준비와 분할 / 스냅샷

B가 늦게 시작해도 A와 같은 시점의 구매를 읽으려면 어떻게 할까요?

계획을 만드는 순간 주간 구매를 한 번 복사해 둡니다. A와 B는 그 사본에서 각자 맡은 주문을 읽고, 중간에 멈췄다가 다시 시작해도 같은 사본을 사용합니다.

이 장의 용어

스냅샷
한 판본의 계산에 사용할 구매 품목을 따로 저장한 사본입니다.
커밋
여러 변경을 데이터베이스에 한꺼번에 확정하는 일입니다. 확정된 구매는 이후에 시작하는 다른 작업도 읽을 수 있습니다.
체크섬
입력값과 순서로 계산한 지문입니다. 행 수가 같아도 내용이 바뀌면 검산에서 찾아낼 수 있습니다.

계획을 만드는 도중 실패하면 절반만 복사된 사본을 읽게 될까요?

MySQL 시험에서 두 번째 주문 구간을 저장할 때 강제로 실패시키자 계획·복사 행·경계가 함께 취소됐습니다. 두 서버 모두 부분 사본을 읽지 않았고, 같은 판본 번호로 다시 요청해 완성된 사본을 만들 수 있었습니다.

구현과 검증 근거

  • 입력을 하나의 읽기 시점에 복사하는 쿼리
  • 복사 도중 주문 11을 넣는 실제 MySQL 시험
  • 공통 사본을 선택한 이유
