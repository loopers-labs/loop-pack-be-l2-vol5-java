점수 계산과 고객 공개 / 배치 멱등성

B가 3점을 두 번 보내도 왜 8점이 되지 않을까요?

B가 보내는 3점은 자기 주문 구간에서 상품 7을 산 전체 수량입니다. 저장소는 같은 구간의 같은 상품에 이미 3점이 있는지 확인하므로, 재전달 후에도 A의 2점과 B의 3점만 남습니다.

이 장의 용어

멱등성
같은 작업을 여러 번 적용해도 최종 결과가 한 번 적용했을 때와 같은 성질입니다.
행의 키
저장된 기록 한 줄을 찾는 주소입니다. 이 표에서는 구매 사본의 식별자(ID), 주문 구간 번호, 상품 번호를 함께 씁니다.
충돌 기록
같은 키로 다른 값이 도착했을 때, 처음 값과 새로 시도한 값을 따로 남기는 기록입니다.

실제 재시작 때마다 B가 같은 점수를 다시 쓰나요?

운영 설정은 이미 완료된 작업 단계를 건너뜁니다. 두 서버 시험에서는 B의 완료된 단계도 한 번 더 실행하도록 설정해, 같은 쓰기가 저장소까지 실제로 도착해도 점수가 유지되는지 확인했습니다.

구현과 검증 근거

  • 두 서버에서 같은 3점을 실제로 재전달한 기록
  • 다른 값 4를 시도하고 기존값 3을 확인한 시험
  • 재전달된 값과 최종 5점을 읽은 두 프로세스 시험
