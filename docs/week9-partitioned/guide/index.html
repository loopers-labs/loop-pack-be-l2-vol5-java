이 서비스는 지난주에 팔린 수량을 상품별로 더해 순위를 매깁니다. 여러 주문을 모아 처리하는 일을 배치라고 합니다. 상품 7을 두 주문에서 2개와 3개 샀다면, 서버가 일을 나누고 재시도한 뒤에도 정답은 5점입니다.

Spring Batch를 처음 본다면 · Job, Step, 청크
Job · 한 작업
Spring Batch는 묶음 처리를 실행하는 자바 도구입니다. 이 프로젝트에서 한 JVM은 자신에게 배정된 주문 구간 하나를 Job으로 실행합니다.
Step · 작업 안의 단계
고정 입력을 확인하거나 상품별 점수를 쓰는 단위입니다. 한 JVM에서 상품 범위별로 여러 작업자 Step을 동시에 실행할 수 있습니다.
청크 · 함께 저장할 묶음
예를 들어 두 상품씩 처리하면 두 점수와 읽기 위치를 함께 확정합니다. 다음 묶음에서 실패해도 앞서 저장한 두 상품은 기억합니다. 재시작 위치 따라가기

실행 준비와 분할

  1. 스케줄러두 서버가 동시에 월요일을 맞으면 누가 랭킹 계산을 시작할까요?
  2. 스냅샷B가 늦게 시작해도 A와 같은 시점의 구매를 읽으려면 어떻게 할까요?
  3. 배치 파티셔닝두 서버는 왜 주문을 나누고, 서버 안에서는 왜 상품을 나눌까요?

점수 계산과 고객 공개

  1. 배치 정합성합계가 5점인데도 공개를 멈추는 이유는 뭘까요?
  2. 배치 멱등성B가 3점을 두 번 보내도 왜 8점이 되지 않을까요?
  3. 검산과 고객 공개계산 중에 고객이 조회하면 어느 랭킹을 볼까요?

시간과 실행이 어긋날 때

  3. 실패와 장애 인수한 서버가 응답을 멈추면 다른 서버는 언제 이어받을까요?
