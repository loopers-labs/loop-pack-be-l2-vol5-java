시간과 실행이 어긋날 때 / 실패와 장애 인수

한 서버가 응답을 멈추면 다른 서버는 언제 이어받을까요?

작업 중인 서버의 생존 신호가 끊겨도, 다른 서버가 곧바로 같은 구간을 계산하면 두 서버가 겹쳐 쓸 수 있습니다. 이전 서버의 종료를 확인하고 저장 기록을 대조해야 새 서버가 남은 상품을 안전하게 처리할 수 있습니다.

이 장의 용어

생존 신호(heartbeat)
배치 서버가 주기적으로 DB에 남기는 활동 기록입니다. 신호가 늦어지는 원인에는 네트워크 지연도 있습니다.
실행 ID
배치를 실행한 한 번의 시도에 붙이는 번호입니다. 같은 작업을 재시작하면 새 번호가 생깁니다.
세대 번호
구간의 실행권을 새로 받을 때 올라가는 번호입니다. 점수를 쓸 때 현재 담당자와 세대가 일치하는지 검사합니다.

배치 기록에 실패(FAILED)가 찍히면 서버도 종료됐다는 뜻일까요?

FAILED는 그 실행이 실패로 끝났다는 기록입니다. 별도의 두 서버 시험에서는 점수를 쓰는 작업자(worker)가 3점을 커밋한 뒤 전체 작업을 관리하는 단계(manager)가 실패했고, 같은 서버가 재시도했습니다. 반대로 서버 자체가 종료돼 마지막 상태가 STARTED에 머물면 위의 인수 절차를 따릅니다.

구현과 검증 근거

  • 중단된 주문 구간을 인수하는 운영 절차
  • 이전 서버를 종료하고 다른 서버가 17개를 처리한 테스트
  • 완료된 worker의 3점을 재전달한 별도 시험
