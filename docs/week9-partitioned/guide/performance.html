성능 측정

작업자가 넷인데 왜 두 서버가 더 오래 걸렸을까요?

여기서는 배치 앱을 실행하는 자바 프로세스(JVM)를 한 서버로 셉니다. 작업자(worker)는 자기 몫의 상품을 계산합니다. 두 서버 실험에서는 512개 상품이 양쪽 주문 구간에 모두 들어 있어 저장할 점수가 1,024행으로 늘었습니다.

계획 시작부터 고객에게 공개될 때까지

같은 상품을 몇 번 계산했을까요?

상품 7이 두 주문 구간에 모두 있으면 각 구간에서 한 번씩 수량을 셉니다. 최종 점수는 두 부분 점수를 더해 얻습니다.

시간을 비교하기 전에 정답을 비교합니다

세 구성 모두 같은 구매를 읽고 같은 점수와 순위를 공개했습니다. 구매 내역과 완성 순위를 각각 일정한 순서로 나열해 지문(SHA-256)을 구한 뒤, 예상한 지문과 일치하는지 확인했습니다.

두 병렬 구성의 공개 시간 차이는 약 1.083초였습니다. 그중 약 0.987초의 차이가 첫 worker 시작부터 마지막 worker 종료 사이에서 관측됐습니다. 이 구간에는 DB 연산과 대기도 포함됩니다. 개별 쿼리나 잠금이 차지한 시간은 따로 측정하지 않았습니다.
