# 설계 변경·승인·구현 이력

기존 절 번호 참조: [2.8](../features/order-payment/pg-client.md#28-pg-http-도구와-테스트-서버의-구성) · [2.9](../features/order-payment/pg-client.md#29-http-제한과-pg-회로의-초기-정책) · [5.5](../features/pg-simulator/README.md#55-로컬-pg-http-계약) · [5.7](../features/pg-simulator/fixture-contract.md#57-테스트-pg-제어와-상태-보존).

기존 문서의 계약·절 번호·승인/검증 상태를 보존해 이동했다. 재편 자체는 제품 계약 변경이나 새 실행 검증을 뜻하지 않는다.

아래 날짜·검사 결과·진척 문장은 당시 기록이다. 이번 문서 재편의 실행 결과로 해석하지 않는다.

2026-10-06 브랜드 일괄 삭제에 이어 주문 확정·동시성 설계를 확정했다. Order·Point·Product의 비관적 잠금, 공통 변경 경로, 쿼리 선택 기준과 검증 기준·완료 근거는 [4.3](../features/order-payment/processing.md#43-주문-확정)에, 선택 이유와 비용은 [부록 A.3](../decisions/domain-and-api.md#a3-주문-확정의-포인트재고-처리-순서)에 둔다. 설계 문서 세트만으로 구현 기준을 확인할 수 있으며 별도 검토 노트에 의존하지 않는다.

2026-10-07 브랜드 일괄 삭제의 구현·검증을 완료했다. infrastructure의 native SQL bulk와 Brand 삭제를 하나의 트랜잭션에서 처리하며, 실제 bulk 이후 실패의 rollback, 삭제 후 사용 제한·과거 주문 보존·HTTP 접근 경계를 검증했다. 브랜드 인계 시점의 전체 검사 결과는 326건·실패/오류/skip 0이며 Checkstyle·ArchUnit도 통과했다. 브랜드 bulk의 인덱스 실행계획 확인 항목은 사용자 결정에 따라 실제 데이터의 bulk 동작 테스트, 단독 인덱스 생성·중복 없음, 빈 테이블 EXPLAIN을 근거로 인정했다. 데이터가 있는 조건의 실행계획·탐색 효율·성능과 브랜드 삭제의 동시 경쟁은 미검증이다. 삭제 Brand 아래 미삭제 Product가 남는 경우, 조회에서는 숨겨지지만 상품 ID 기반 명령에서 사용될 가능성은 남아 있다([4.1.4](../features/catalog.md#414-삭제-이후-사용-제한과-조회-방어)·[4.1.5](../features/catalog.md#415-동시성-범위와-향후-대안)). 실행계획 확인 범위와 한계는 [4.1.6](../features/catalog.md#416-인덱스와-설계-재검토-기준), 검증 기준과 완료 근거는 [4.1.7](../features/catalog.md#417-검증-계획)에 둔다.

2026-10-07 주문 확정·동시성의 구현·검증을 완료했다. `Order → Point → Product` 순서의 비관적 쓰기 잠금을 적용하고, 포인트 충전과 상품 수정·삭제·최종 재고 설정도 같은 행 잠금에 참여한다. 최종 `cleanTest check`의 저장된 테스트 결과는 353건·실패/오류/skip 0이며 ArchUnit 3건이 통과했다. Checkstyle은 직전 검사 통과 이후 Java 소스 변경이 없어 최종 실행에서 UP-TO-DATE였다. 실제 SQL 이후 rollback, 경쟁 결과와 자원 정리의 완료 근거·미검증 한계는 [4.3.5](legacy-point.md#435-구현-단계-검증-계획)에 둔다.

2026-10-15 고객 상세의 상품명·Brand 이름·가격·재고만 JSON String cache-aside로 저장하고 좋아요 수는 DB 조회로 합성하기로 했다. 기본정보 영향 쓰기는 공통 afterCommit callback에서 commit 뒤 동기 DEL한다. TTL은 시험 10초/평시 5분의 고정값이며 hit에서 연장하지 않는다. 평시/일반 회귀는 cache on·필요한 캐시 비교만 DB-only, cold는 기본 miss+동시 miss 관측이다. 기존 master·초기 connect/command 200ms 실측·실패 로그/재시도 없음·기존 로컬 MySQL/Redis·loopers 공유를 사용하고 CPU 수집은 모두 제외한다. 구현된 SQL/포트/TX 경계와 확인한 데이터/표본은 [4.4 상품 조회](../features/product-cache.md#44-상품-조회)와 연결된 실행 기록을 따른다.

2026-10-15 상품 조회의 기능 구현·변경/실패/복구·회귀 검증을 완료했다. 목록 SQL은 유지하고 인덱스를 추가했으며(2026-10-16 라이팅 실험에서 고른 product `(brand_id, price)`·`(brand_id, created_at)`·`(brand_id, deleted_at)`, product_like `(product_id)`로 정리), 상세 기본정보 cache-aside와 영향 쓰기의 commit 뒤 DEL을 구현했다. 변경·rollback·DEL 실패·늦은 fill은 실제 Spring·MySQL·Redis 통합 테스트로, Redis 중단·재시작은 로컬 앱으로 확인했다. 최종 `cleanTest check`는 377건·fail/error/skip 0이다. 목록 전후 반복 지연·전체 응답 비교는 보완이 필요하고, 캐시의 전체 SQL 수·읽은 행 수 감소나 지연 향상은 입증되지 않았다. 글을 준비하며 SQL 실험과 남은 제출 근거를 보완한다. 2026-10-16 목록 전후 비교(E0)를 실제 API로 채웠고, 캐시 hit의 비싼 원본 호출 감소 조건은 미충족으로 판정해 정책을 유지했다. 구체 구성과 한계는 [4.4](../features/product-cache.md#44-상품-조회)에 둔다.

2026-10-23 현재 구현 상태: 최종 설계는 2026-10-22 사용자 승인을 받았으며 I1 fixture·I2 HTTP/회로 adapter·I3 저장/TX에 이어 I4 confirm/callback/reconcile·고객/관리자 응답을 구현했다. I4 전체 회귀 752건·실패/오류/skip 0, 캐시 준비 보강 후 관련 9건·위반 0을 확인했다. 상세 실행 경계·기존 POINT 테스트 전환·미검증 조건은 [4.5의 I4 근거](payment.md#i4-구현과-검증-근거--2026-10-23)를 따른다. 아래 문서 구성의 작성 당시 미구현·승인 대기 설명은 당시 이력이며, I5의 경쟁/회복/재시작 전체 검증과 I2·I3 Codex 일괄 검토를 완료로 뜻하지 않는다.

2026-10-23 I5도 경쟁·장애 회복·DB/PG 유지 재시작과 관련 회귀를 완료했다. 저장 품목 정합성 검사 누락을 기존 계약대로 보완했으며 제품 정책/timeout/회로 값은 유지했다. 전체 회귀 805건과 최종 I5 보강 56건 및 별도 분류 검증 5건의 실행 범위·자원 종료·허용 한계는 [I5 검증 근거](payment.md#i5-경쟁장애-회복재시작-검증-근거--2026-10-23)를 따른다. 구현 종료 시에는 사용자 요청에 따라 스테이징하지 않았고, 이후 사용자의 추가 요청으로 I5 코드·테스트와 기준 설계의 검증 기록을 스테이징했다. 커밋은 사용자가 직접 수행한다. 아래 I4 시점의 I5 미검증 설명은 당시 이력이다.

2026-10-25 PG 테스트 fixture를 별도 모듈 `apps/pg-simulator`의 단독 실행 앱으로 전환했다. 사용자가 방향과 주요 결정(JDK HttpServer, `amount % 3` 결과 규칙, 자동 처리 지연 1초, PG main에는 확장점만 두고 장애 주입은 테스트 프록시로 분리)을 승인했고 상세 설계는 사용자 검토를 마쳤다. 같은 날 R1(PG 모듈)·R2(기존 테스트 fixture를 테스트 래퍼·프록시로 교체) 구현, R3(전체 회귀·실험 테스트), R4(수동 실행), R5(최종 회귀)를 마쳤다. 구현 중 callbackSent 집계 시점 변경을 사용자 결정으로 추가했다(5.7). 실행 근거는 [4.5 전환 검증](pg-simulator.md#pg-단독-실행-앱-전환의-검증--2026-10-25-목표)에 둔다. 기준은 [2.10](../features/pg-simulator/README.md#210-pg-시뮬레이터-앱의-책임과-수명)·[5.7](../features/pg-simulator/fixture-contract.md#57-테스트-pg-제어와-상태-보존)·[A.33](../decisions/pg-simulator.md#a33-pg-단독-실행-앱으로의-전환)이며, 5.5 계약·commerce-api main 코드·기존 테스트 기대값은 바뀌지 않는다.

2026-10-23 후속 검토에서 저장 결제 금액 정합성 누락(F5)을 기존 계약대로 보완했고, Claude 검토의 유효한 테스트 공백·최종 Apache 설정의 재현 가능한 근거·낡은 현재 상태 문구도 정리했다. I5는 사용자가 715bd0e로 커밋한 상태이며 이 후속 변경은 미스테이징·미커밋이다. 최종 check 829건·실패/오류/skip 0, Checkstyle·ArchUnit 통과의 경계는 [F5·Claude 검토 보완 근거](payment.md#f5claude-검토-보완과-최종-회귀--2026-10-23)를 따른다. PR·기술 글 작성은 별도 미완료다.
