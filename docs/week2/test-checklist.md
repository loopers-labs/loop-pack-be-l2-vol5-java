# 2주차 핵심 테스트 체크리스트

## 포인트

- [x] 단위: 양수 금액을 충전하면 잔액이 증가한다
- [ ] 단위·통합: 기존 10,000원에 5,000원을 추가 충전하면 15,000원이 된다
- [x] 단위: 충전 합산 범위를 넘으면 기존 잔액을 유지한다
- [x] 단위: 포인트를 차감하면 잔액이 감소한다
- [x] 단위: 잔액보다 많이 차감하면 거절하고 잔액을 유지한다
- [ ] 통합: 충전 API 결과와 DB에서 다시 조회한 잔액이 일치한다
- [ ] 통합: 대표적인 충전 입력 오류를 거절하고 기존 잔액을 유지한다

- [ ] 통합: 잔액 행이 없으면 저장 없이 0원을 조회하고 첫 충전 시 저장한다

## 브랜드

- [ ] 단위: 미삭제 상품이 연결돼 있으면 브랜드 삭제를 거절한다
- [ ] 단위: 삭제할 수 있는 브랜드는 소프트 삭제된다
- [ ] 통합: 브랜드를 등록·수정한 결과를 다시 조회할 수 있다
- [ ] 통합: 재고가 0이어도 미삭제 상품이 연결돼 있으면 삭제를 거절한다
- [ ] 통합: 고객이 삭제된 브랜드를 상세 조회하면 BRAND_NOT_FOUND로 거절한다
- [ ] 통합: 관리자는 삭제된 브랜드를 목록·상세에서 삭제 상태와 함께 조회한다
- [ ] 통합: 대표 브랜드 API에서 관리자 허용과 일반·미식별 요청 거절을 확인한다

## 상품

- [ ] 단위: 상품 정보를 수정해도 브랜드는 유지한다
- [ ] 단위: 재고를 0 이상의 최종 수량으로 설정한다
- [ ] 단위: 재고 5개에서 2개를 차감하면 3개가 남는다
- [ ] 단위: 재고 5개에서 6개를 차감하면 거절하고 재고를 유지한다
- [ ] 통합: 유효한 브랜드의 상품을 등록하고 변경 결과를 고객 조회에 반영한다
- [ ] 통합: 목록의 브랜드 필터·페이지·정렬을 확인한다
- [ ] 통합: 최신순은 생성 시각을 우선하고, 시각이 같을 때만 ID 역순으로 정렬한다
- [ ] 통합: 삭제된 상품은 고객 조회와 수정·재고 변경에서 제외한다
- [ ] 통합: 관리자는 삭제된 상품을 목록·상세에서 삭제 상태와 함께 조회한다

## 좋아요

- [ ] 단위: application에서 반복 등록·취소, 삭제 상품 처리, 요청자별 관계·조회 범위를 확인한다

- [ ] 통합: 좋아요를 등록하면 사용자–상품 관계와 좋아요 수에 반영한다
- [ ] 통합: 존재하는 상품에도 식별 헤더가 없으면 INVALID_REQUEST로 거절하고 저장하지 않는다
- [ ] 통합: 유효한 상품에 좋아요를 반복 등록해도 200으로 성공하며 관계는 하나이고 좋아요 수는 추가로 증가하지 않는다
- [ ] 통합: 본인의 좋아요를 취소하면 관계와 좋아요 수에 반영한다
- [ ] 통합: 본인의 좋아요 관계가 없어도 취소 요청은 200으로 성공하고 저장 상태는 바뀌지 않는다
- [ ] 통합: 본인 목록만 조회하고 삭제된 상품은 목록에서 제외한다
- [ ] 통합: 삭제된 상품의 신규 좋아요는 거절하고 남은 본인 관계의 취소는 허용한다

## 주문

- [ ] 단위: 품목이 없는 주문 생성을 거절한다
- [ ] 단위: 주문 수량이 0 이하이면 중복 상품 수량을 합산하기 전에 거절한다
- [ ] 단위: 같은 상품의 수량을 합쳐 한 품목으로 만든다
- [ ] 단위: 품목 단가·수량으로 주문 합계를 계산한다
- [ ] 단위: 주문을 생성하면 DRAFT 상태다
- [ ] 단위: 주문을 확정하면 결제액·결과와 CONFIRMED 상태를 기록한다
- [ ] 통합: 주문 생성 시 품목·수량·생성 당시 단가·합계를 저장하고 재고·포인트는 차감하지 않는다
- [ ] 통합: 단가 2,000원으로 2개 주문한 뒤 상품 가격이 3,000원으로 바뀌어도 생성 당시 단가로 4,000원을 결제한다
- [ ] 통합: DRAFT 생성 뒤 상품이 삭제되면 최초 확정을 거절하고 주문·재고·포인트를 기존 상태로 유지한다
- [ ] 통합: 충전 10,000원에서 여러 품목 7,000원을 결제하면 CONFIRMED 주문과 잔액 3,000원을 조회한다
- [ ] 통합: 재고 부족 시 주문·재고·포인트를 모두 기존 상태로 유지한다
- [ ] 통합: 잔액 부족 시 주문·재고·포인트를 모두 기존 상태로 유지한다
- [ ] 통합: 고객 주문 목록에는 본인의 주문만 반환한다
- [ ] 통합: 타인의 주문 상세는 없는 주문과 동일한 ORDER_NOT_FOUND 응답으로 거절한다
- [ ] 통합: 타인의 주문 확정은 없는 주문과 동일한 ORDER_NOT_FOUND 응답으로 거절하고 주문·재고·포인트를 유지한다
- [ ] 통합: 본인의 확정된 주문에 재요청하면 기존 결과를 반환하고 재고·포인트를 추가로 차감하지 않는다
- [ ] 통합: 관리자는 구매자별 필터로 주문 목록을 조회한다
- [ ] 통합: 관리자는 주문 상세에서 구매자·품목·수량·금액·상태·결제 결과를 조회한다

## 개발 규칙

- [ ] 핵심 규칙의 Red → Green → Refactor를 확인한다
- [ ] 관련 테스트와 Checkstyle·ArchUnit을 통과한다
- [ ] 도메인과 영속성 엔티티를 분리한다
- [ ] 오류 클래스의 HTTP 의존을 제거하고 HTTP 상태 변환은 웹 계층에서 처리한다

- [ ] 테스트: 0원·빈 목록 응답은 필드 존재와 숫자·배열 타입을 확인한다
- [ ] 테스트: 준비·요청·검증을 본문에 명시하고 독립된 행동을 별도 테스트로 검증한다
