# 구현된 유스케이스

이 문서는 현재 구현에서 **고객과 관리자가 얻을 수 있는 결과**를 정리한다. 유스케이스는 Java `*UseCase` 클래스나 HTTP 엔드포인트의 개수에 맞추지 않고, 행위자의 목적과 관찰 가능한 결과로 구분한다. 출처는 [요구사항](./requirements.md)이고, 정확한 입력·응답·오류는 [API 계약](./api-contract.md), 결과가 지켜야 할 조건은 [도메인 규칙](./domain-rules.yaml)에 있다.

고객 요청은 사용자를 식별해야 하며 고객은 자신의 좋아요·포인트·주문만 다룬다. 관리자 요청은 `ADMIN` 역할이 필요하다. 접근 실패는 [API 공통 규칙](./api-contract.md#요청자-식별)을 따른다.

## 고객이 얻는 결과

| 목적 | 구현된 결과 | 실패·예외 | 출처·API |
| --- | --- | --- | --- |
| 브랜드 정보 확인 | 삭제되지 않은 브랜드의 상세 정보를 본다. | 없거나 삭제된 브랜드는 조회하지 못한다. | `R-CATALOG-01` · [C-01](./api-contract.md#c-01-브랜드-상세) |
| 상품 탐색 | 삭제되지 않은 상품의 목록·상세를 보고, 브랜드·좋아요 수·품절 여부를 확인한다. 목록은 브랜드와 정렬 기준으로 좁힌다. | 삭제된 상품은 고객 조회에서 빠지고, 잘못된 목록 조건은 거절된다. | `R-CATALOG-02`~`R-CATALOG-08` · [C-02](./api-contract.md#c-02-상품-목록), [C-03](./api-contract.md#c-03-상품-상세) |
| 좋아요 등록 | 활성 상품에 자신의 좋아요 관계가 생긴다. 이미 등록했다면 관계와 좋아요 수는 그대로다. | 없거나 삭제된 상품에는 새로 등록하지 못한다. | `R-LIKE-01`, `R-LIKE-02`, `P-LIKE-01` · [C-04](./api-contract.md#c-04-좋아요-등록) |
| 좋아요 취소 | 자신의 좋아요 관계가 취소되고 좋아요 수에 반영된다. 상품이 삭제됐거나 이미 취소했어도 요청을 마칠 수 있다. | 다른 고객의 관계는 바꾸지 않는다. | `R-LIKE-01`, `R-LIKE-04`, `R-LIKE-08` · [C-05](./api-contract.md#c-05-좋아요-취소) |
| 내 좋아요 확인 | 자신의 활성 좋아요에 연결된 상품 목록을 본다. 삭제된 상품은 목록에서 빠진다. | 다른 고객의 목록은 조회하지 못한다. | `R-LIKE-03`, `R-LIKE-07` · [C-06](./api-contract.md#c-06-내-좋아요-목록) |
| 포인트 충전 | 충전액만큼 자신의 잔액이 늘고 충전 후 잔액을 확인한다. | 금액이 유효하지 않거나 잔액의 표현 범위를 넘으면 잔액은 그대로다. | `R-POINT-01`, `R-POINT-06`~`R-POINT-08` · [C-07](./api-contract.md#c-07-포인트-충전) |
| 내 잔액 확인 | 저장된 현재 잔액을 본다. 충전한 적이 없으면 0이다. | — | `R-POINT-02`, `P-POINT-01` · [C-08](./api-contract.md#c-08-내-잔액-조회) |
| 주문 생성 | 활성 상품의 품목으로 `DRAFT` 주문이 생긴다. 같은 상품은 수량을 합치고 상품 이름·단가는 생성 당시 값으로 남긴다. 재고와 잔액은 그대로다. | 품목이 없거나 수량이 유효하지 않거나 상품이 없거나 삭제됐으면 주문을 만들지 않는다. | `R-ORDER-01`~`R-ORDER-06`, `R-ORDER-15` · [C-09](./api-contract.md#c-09-주문-생성) |
| 주문 확정 | 자신의 `DRAFT` 주문이 결제 결과를 가진 `CONFIRMED`가 되고, 상품 재고와 자신의 포인트가 함께 차감된다. | 다른 고객의 주문, 이미 확정된 주문, 삭제된 상품, 재고·잔액 부족이면 거절하고 주문·재고·잔액을 그대로 둔다. | `R-ORDER-07`~`R-ORDER-12` · [C-10](./api-contract.md#c-10-주문-확정) |
| 내 주문 확인 | 자신의 주문 목록·상세와 주문 당시 저장한 품목 정보를 본다. 상품이 나중에 삭제돼도 품목 정보는 남는다. | 다른 고객의 주문은 조회하지 못한다. | `R-ORDER-13`, `R-ORDER-14` · [C-11](./api-contract.md#c-11-내-주문-목록), [C-12](./api-contract.md#c-12-내-주문-상세) |

## 관리자가 얻는 결과

| 목적 | 구현된 결과 | 실패·예외 | 출처·API |
| --- | --- | --- | --- |
| 브랜드 정보 확인 | 삭제된 브랜드를 포함한 목록·상세와 삭제 여부를 본다. | 존재한 적 없는 브랜드의 상세는 조회하지 못한다. | `R-ADMIN-01`, `P-ADMIN-07` · [A-01](./api-contract.md#a-01-브랜드-목록), [A-03](./api-contract.md#a-03-브랜드-상세) |
| 브랜드 생성 | 유효한 이름으로 새 활성 브랜드가 생긴다. 삭제된 브랜드의 이름은 다시 사용할 수 있다. | 활성 브랜드와 이름이 같으면 거절한다. | `R-ADMIN-01`, `R-ADMIN-15`, `P-ADMIN-01` · [A-02](./api-contract.md#a-02-브랜드-생성) |
| 브랜드 수정 | 활성 브랜드의 이름이 바뀌고 이후 고객 조회에 새 이름이 보인다. | 삭제된 브랜드이거나 다른 활성 브랜드와 이름이 같으면 거절한다. | `R-ADMIN-01`, `R-ADMIN-09`, `R-ADMIN-13` · [A-04](./api-contract.md#a-04-브랜드-수정) |
| 브랜드 삭제 | 활성 상품이 없는 브랜드가 논리 삭제되고 고객 조회에서 빠진다. 저장된 참조는 남는다. | 활성 상품이 있거나 이미 삭제된 브랜드는 삭제하지 못한다. | `R-ADMIN-02`, `R-ADMIN-03`, `R-ADMIN-14` · [A-05](./api-contract.md#a-05-브랜드-삭제) |
| 상품 정보 확인 | 삭제된 상품을 포함한 목록·상세, 재고와 삭제 여부를 본다. | 존재한 적 없는 상품의 상세는 조회하지 못한다. | `R-ADMIN-04`, `P-ADMIN-07` · [A-06](./api-contract.md#a-06-상품-목록), [A-08](./api-contract.md#a-08-상품-상세) |
| 상품 생성 | 활성 브랜드에 새 상품이 생기며 처음 재고는 0이다. 삭제된 상품의 이름은 다시 사용할 수 있다. | 브랜드가 없거나 삭제됐거나, 같은 브랜드의 활성 상품과 이름이 같거나 이름·가격이 유효하지 않으면 거절한다. | `R-ADMIN-05`, `R-ADMIN-06`, `P-ADMIN-02` · [A-07](./api-contract.md#a-07-상품-생성) |
| 상품 수정 | 활성 상품의 이름·가격이 바뀌고 이후 고객 조회에 반영된다. 재고와 소속 브랜드는 그대로다. | 삭제된 상품, 유효하지 않거나 중복된 이름, 유효하지 않은 가격, 브랜드 변경 요청은 거절한다. | `R-ADMIN-06`, `R-ADMIN-07`, `R-ADMIN-09`, `P-ADMIN-02` · [A-09](./api-contract.md#a-09-상품-수정) |
| 상품 삭제 | 상품이 논리 삭제되고 고객 조회와 새 주문에서 빠진다. 기존 좋아요·주문 품목은 남는다. | 이미 삭제된 상품은 다시 삭제하지 못한다. | `R-ADMIN-12`~`R-ADMIN-14` · [A-10](./api-contract.md#a-10-상품-삭제) |
| 상품 재고 변경 | 활성 상품의 재고가 지정한 최종 수량으로 바뀐다. | 삭제된 상품이거나 최종 수량이 음수이면 거절한다. | `R-ADMIN-08` · [A-11](./api-contract.md#a-11-상품-재고-변경) |
| 주문 정보 확인 | 전체 주문 또는 특정 구매자의 주문을 목록으로 보고, 주문 상세와 결제 결과를 확인한다. | 존재하지 않는 주문 상세는 조회하지 못한다. | `R-ADMIN-10`, `R-ADMIN-11` · [A-12](./api-contract.md#a-12-주문-목록), [A-13](./api-contract.md#a-13-주문-상세) |

브랜드·상품 이름은 현재 활성 대상만 비교한다. 동시 요청에서 중복을 막는 DB 보장 방식은 [ADR-001의 미결정 사항](./decisions.md#adr-001-브랜드상품은-논리-삭제한다)에 남아 있다. 여러 결과가 이어지는 과정은 [대표 흐름](./representative-flows.md)에 정리돼 있다.
