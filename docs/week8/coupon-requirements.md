# 쿠폰 발급 요구사항 및 API 계약

## 요구사항


| ID          | 요구사항                                | 출처                                               |
| ----------- | ----------------------------------- | ------------------------------------------------ |
| R-COUPON-01 | 한 사용자는 같은 캠페인에서 쿠폰을 한 장만 발급받을 수 있다. | 8주차 과제 · `1. 쿠폰 규칙과 API`                         |
| R-COUPON-02 | 캠페인의 현재 발급 수는 총 발급 한도를 넘을 수 없다.     | 8주차 과제 · `1. 쿠폰 규칙과 API`, `2. DB에서 발급 총량과 중복 보호` |


## 도메인 규칙

| 규칙 ID | 책임 개념 | 규칙 |
| --- | --- | --- |
| `INV-COUPONCAMPAIGN-52` | `CouponCampaign` | 캠페인의 현재 발급 수는 총 발급 한도 이하다. |
| `INV-COUPON-53` | `Coupon` | 한 사용자와 한 캠페인의 조합에 발급된 쿠폰은 최대 한 장이다. |
| `INV-COUPON-54` | `Coupon` | 이미 쿠폰을 발급받은 사용자의 같은 캠페인 재요청은 기존 쿠폰을 반환하고 캠페인 발급 수를 늘리지 않는다. |
| `INV-COUPON-55` | `Coupon` | 캠페인이 품절·비활성화되어도 기존 쿠폰은 해당 사용자의 보유 목록에서 조회되며 발급 기록으로 확인된다. |


## 데이터 모델


| 데이터 | 필드                                 | 비고                         |
| --- | ---------------------------------- | -------------------------- |
| 캠페인 | ID, 이름, 발급 가능 여부, 총 발급 한도, 현재 발급 수 | 총 발급 한도는 캠페인별 설정 값으로 조정한다. |
| 쿠폰  | ID, 발급 시각, 사용자, 캠페인, 혜택 정보         | 혜택 정보는 발급된 쿠폰에 보존한다.       |


## API 계약

### 공통


| 항목    | 계약                                                                                        |
| ----- | ----------------------------------------------------------------------------------------- |
| 고객 식별 | 기존 고객 API와 같이 `X-USER-ID` 요청 헤더를 사용한다. 별도 userId를 요청에 넣어 다른 사용자에게 발급하거나 조회할 수 없다.         |
| 쿠폰 표현 | `{ "id": 1, "issuedAt": "발급 시각", "userId": 1, "campaignId": 1, "benefit": "5,000원 할인권" }` |
| 성공 응답 | 기존 공통 형식의 `meta.result=SUCCESS`와 API 결과를 담은 `data`를 사용한다.                                 |
| 실패 응답 | 기존 공통 형식의 `meta.result=FAIL`, `meta.errorCode`, `meta.message`, `data=null`을 사용한다.        |


공통 응답 형식은 [기존 API 계약](../week2/api-contract.md#응답-계약)을 따른다.

### 캠페인 쿠폰 발급


| 항목              | 계약                                                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 요청              | `POST /api/v1/coupon-campaigns/{campaignId}/issues`                                                                           |
| 입력              | path `campaignId`; 요청 본문 없음                                                                                                   |
| 최초 발급           | `201 Created`, 발급된 쿠폰을 반환한다.                                                                                                  |
| 같은 사용자·캠페인의 재요청 | `200 OK`, 기존 쿠폰과 같은 `id`를 반환하고 발급 수를 늘리지 않는다.                                                                                 |
| 캠페인 오류          | 존재하지 않는 캠페인은 `404 COUPON_CAMPAIGN_NOT_FOUND`; 비활성 캠페인은 `409 COUPON_CAMPAIGN_INACTIVE`; 품절 캠페인은 `409 COUPON_CAMPAIGN_SOLD_OUT` |
| 처리 수용 오류        | 처리 자리가 없으면 `429 COUPON_ADMISSION_FULL`; Redis 수용 상태를 확인할 수 없으면 `503 COUPON_ADMISSION_UNAVAILABLE`                             |


### 내 쿠폰 목록


| 항목  | 계약                                    |
| --- | ------------------------------------- |
| 요청  | `GET /api/v1/coupons`                 |
| 입력  | query 없음. userId 입력은 받지 않는다.          |
| 성공  | `200 OK`, 요청한 사용자의 보유 쿠폰 목록을 반환한다.    |
| 순서  | 발급 시각 내림차순, 발급 시각이 같으면 쿠폰 ID 내림차순     |
| 오류  | 고객 식별에 실패하면 `401 USER_NOT_IDENTIFIED` |
