# W8 계획 — 쿠폰 발급 워커 스레드 보호

작성: 2026-11-10, `volume-8`.
목적: 쿠폰 발급 요청이 몰릴 때 워커 스레드를 보호한다. 아래 네 방식을 각각 도입해 비교한다.

배경: 쿠폰 발급 spike 부하 테스트(`loadtest/`)와 발급 트랜잭션 축소(발급 쿠폰 insert + 조건부 재고 차감만 트랜잭션에 포함).

## 도입할 방식

| # | 방식 | 대기열 | 허가 못 받을 때 |
|---|---|---|---|
| 1 | 레디스로 직접 구현한 세마포어 | 없음 | 즉시 실패 (fast-fail) |
| 2 | Redisson 세마포어 | — | — |
| 3 | 직접 구현한 fair 세마포어 | 있음 (도착 순서대로) | 대기 |
| 4 | bulkhead | — | — |

## 미정 항목

구현 전에 정한다.

- 허가(permit) 수
- 대기 타임아웃 (2·3·4)
- 거절 응답과 HTTP 상태 코드
- 서버가 죽었을 때 permit 회수 방법 (TTL·lease)
- 리미터 위치: controller / facade / aspect
- 네 방식을 설정·profile로 바꿔 끼울지 여부
- 방식별 부하 테스트 조건과 비교 지표
