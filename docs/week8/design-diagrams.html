쿠폰 발급: 세마포어는 어디에 달리나

세마포어(자리·permit)에 관련된 부품과 연결 거절되거나 문제가 생기는 곳 점선 테두리 = 애플리케이션 경계

구성도 B. 통합안: ① 로컬 캐시 → ② Redis → ③ outbox → relay → Kafka, 쿠폰 DB는 consumer만

실패 지점 지도: Redis와 DB가 어긋나는 곳

ⓑ 발행 실패 확정 · ⓒ 발행 결과 불명을 처리하는 두 길: 직접 발행 vs 수락분만 outbox

ⓑ 발행 실패 확정: Lua가 수락(사용자·token SADD)한 뒤 API의 Kafka send가 예외로 끝남. 메시지가 없다는 걸 API가 안다.
ⓒ 발행 결과 불명: send가 timeout으로 끝남. Kafka에 들어갔는지 API가 모른다.

outbox가 지켜 주는 범위: "Kafka까지 간다"이지 "쿠폰이 된다"가 아니다

outbox 행은 MySQL에 commit됐으니 메시지는 잃지 않습니다. 하지만 그 앞(Redis)과 뒤(consumer)에서 생기는 실패는 outbox 밖입니다.

실패 지점무슨 일outbox로 막히나결과
ⓐ API가 Lua 수락 뒤 outbox insert 전에 죽음Redis에는 "수락됨"으로 남는데 outbox 행이 없음❌ 그 앞이라 안 됨다시 요청하면 "이미 수락됨"인데 쿠폰은 영영 안 생김. token도 안 돌아옴
ⓓ consumer 재시도 소진 → DLT메시지가 처리되지 못하고 DLT로 감❌ 그 뒤라 안 됨202를 받았는데 쿠폰 없음. token도 안 돌아옴
ⓕ Redis 재시작·유실Redis가 수락한 사람을 잊고 실제보다 적게 셈❌ Redis 문제라 안 됨한 명을 더 받아 줌 → consumer에서 DB 한도에 막힘 → 202를 받았는데 쿠폰 없음
ⓑ 발행 실패 확정 · ⓒ 발행 결과 불명API의 Kafka send 실패·timeout✅ 없어짐 (relay가 재시도)대신 ⓑ′ insert 실패 → 원복 Lua · ⓒ′ commit 불명 → SELECT로 확인
