# 3주차 테스트 체크리스트

## 브랜드 삭제

- [x] 브랜드와 연결된 미삭제 상품을 함께 소프트 삭제한다.
- [x] 재고가 0인 상품도 브랜드 삭제 대상에 포함한다.
- [x] 연결 상품이 없거나 모두 삭제됐어도 브랜드 삭제는 성공한다.
- [x] 없는 브랜드의 삭제 요청은 기존 오류로 거절한다.
- [x] 다른 브랜드와 상품은 변경되지 않는다.
- [x] 브랜드 삭제가 성공하거나 실패해도 다른 브랜드·상품과 과거 주문의 품목·수량·단가·총액·결제 결과는 유지된다.
- [x] 상품 변경 후 브랜드 저장에 실패하면 HTTP 500을 반환한다.
- [x] 실패한 브랜드 삭제는 상품 변경까지 롤백되며, 트랜잭션 종료 후 재조회해도 원상태다.
- [x] 삭제된 브랜드와 상품은 고객의 상세 조회와 목록에서 노출되지 않는다.
- [x] 삭제된 상품의 신규 좋아요와 주문은 거절한다.
- [x] 삭제된 상품에 남긴 기존 좋아요는 취소할 수 있다.
- [x] 관리자 권한이 없는 요청은 거절한다.
- [x] 삭제된 대상의 수정과 재고 변경은 거절한다.

## 브랜드 변경 경쟁

- [x] 상품 등록이 먼저 진행되면 브랜드 삭제는 새 상품까지 함께 삭제한다.
- [x] 브랜드 삭제가 먼저 진행되면 상품 등록은 BRAND_NOT_FOUND로 거절하고 상품 행을 남기지 않는다.
- [x] 브랜드 이름 수정과 삭제가 겹쳐도 삭제된 브랜드가 다시 활성화되지 않는다.

## 주문 확정

- [x] DRAFT 주문 생성은 재고와 포인트를 차감하지 않는다.
- [x] 여러 품목의 주문 확정에서 재고·포인트·주문 상태·결제액·결제 결과가 함께 저장된다.
- [x] 재고 부족으로 확정에 실패하면 앞선 변경도 롤백된다.
- [x] 포인트 부족으로 확정에 실패하면 앞선 변경도 롤백된다.
- [x] 실제 UPDATE 이후 저장 단계에서 오류가 발생하면 재고·포인트·주문 변경이 모두 롤백된다.
- [x] 확정된 주문의 재요청은 INVALID_REQUEST로 거절하고 추가 차감하지 않는다.
- [x] 이전에 조회한 DRAFT로 이미 확정된 주문을 저장하면 INVALID_REQUEST로 거절하고 기존 결제 정보를 유지한다.
- [x] 주문 확정은 상태 검사보다 소유권을 먼저 확인한다.
- [x] 상품 삭제 후 기존 DRAFT 주문을 확정하면 거절하고 재고·잔액·주문 상태를 유지한다.
- [x] 같은 도메인 객체의 confirm()을 두 번 호출하면 두 번째 호출은 거절하고 확정 상태·결제액·결과를 유지한다.

## 재고·포인트 동시 변경

- [x] 같은 상품의 재고를 여러 주문이 경쟁하면 재고 범위에서만 확정되고 나머지는 재고 부족으로 거절된다.
- [x] 같은 잔액을 여러 주문이 경쟁하면 잔액 범위에서만 확정되고 나머지는 잔액 부족으로 거절된다.
- [x] 확정에 성공한 주문만 재고와 포인트가 차감되고 결제 정보가 저장된다.
- [x] 확정에 실패한 주문은 DRAFT와 미결제 상태를 유지한다.
- [x] 같은 주문을 동시에 확정해도 한 요청만 성공하고 재고와 포인트는 한 번만 차감된다.
- [x] 충전과 결제를 동시에 처리하면 두 변경이 모두 잔액에 반영된다.
- [x] 잔액 행이 없는 사용자의 동시 첫 충전은 한 행에 충전액을 모두 반영한다.
- [x] 관리자 재고 설정과 주문 차감은 실제 DB 처리 순서에 맞는 최종 재고를 남긴다.
- [x] 이전 재고를 가진 객체로 상품 정보를 수정해도 최신 재고를 덮어쓰지 않는다.
- [x] 상품을 삭제해도 최신 재고를 이전 값으로 덮어쓰지 않는다.
- [x] 경쟁 요청의 성공·업무 거절·기술 오류를 구분하고 최종 DB 상태가 요청 결과와 일치한다.

## 좋아요 등록

- [x] 같은 좋아요를 동시에 등록해도 모든 요청이 성공하고 관계는 하나만 저장된다.
- [x] 이미 등록한 좋아요를 다시 등록해도 성공하고 관계는 하나만 유지된다.
- [x] 삭제된 상품의 좋아요 등록은 기존 오류로 거절한다.

## 조회·응답

- [x] 잘못된 페이지와 크기의 목록 조회 요청은 INVALID_REQUEST로 거절한다.
- [x] 목록 조회의 필터와 정렬 조건 검증은 유지된다.
- [x] 확정 주문의 결제 결과는 DB와 API 응답에서 SUCCESS로 유지된다.
- [x] DRAFT 주문의 결제 결과는 null이며 API 응답에서 생략된다.

## 동시성 대조군·계층 의존

- [x] 제어 없는 읽기·쓰기 방식에서 재고 갱신 유실을 재현한다.
- [x] 도메인은 JPA와 HTTP 계층에 의존하지 않는다.
- [x] 애플리케이션·인터페이스·인프라 계층의 의존 규칙을 지킨다.
