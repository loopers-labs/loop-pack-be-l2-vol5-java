# R02 설계 질문·결정 목록

상태: **R02 로컬 구현·검증 완료, 원격 게시 전**. R01은 PR #24로 병합됐고 `4b81541`에서 R02 브랜치를 생성했다. [실제 결과](../result.md)에 전체 검사 432건과 실서버 실험 10개를 기록했다.
준비 TX의 주문 상태 CAS·재고 복구 실패 시 수동 처리·고객 헤더 기반 소유권 검사를 확정했다.
타인 주문은 없는 주문과 같은 404, 주문 관련 관리자는 기존 1번 fixture로 확정했다. 공통 결과 반영도 주문 상태 CAS로 확정했다. callback은 요청 안의 동기 처리로 확정했다. 수동 대사도 저장 종결 결과 재적용은 조회 0회, 그 외 최대 1회로 확정했다. 주요 문답과 상세 계획 초안의 세 관점 리뷰를 마쳤으며 중요 보완 3건은 사용자 승인으로 계획에 반영했다. 세 관점 재리뷰에서도 중요 지적 없이 구현 진행 가능으로 확인했다.
세부 API·클래스·저장/검증 순서는 [상세 계획](../plan.md), 중요한 기능 보완의 승인과 세 관점 재리뷰는 [리뷰 기록](../review.md)을 따른다.

## 확정한 제약

- 재고를 먼저 차감해 commit한 뒤 PG를 호출한다. 성공 시 유지, 확정 실패 시 한 번 복구, 미확인 시 차감 상태 유지다.
- 외부 HTTP는 DB TX 밖에서 실행한다. 주문당 한 시도이며 발송 시작 후 create를 자동 재시도하지 않는다.
- 준비 진입은 주문 `DRAFT → PAYMENT_PENDING` CAS로 선점한다. 기존 상품 잠금·복구 작업 CAS·관찰 저장 잠금은 유지한다.
- 복구 한도 초과는 업무 TX 전체를 rollback하고 저장된 PG 실패를 보존해 수동 처리한다. 관리자 설정의 반환 예정량 집계 제한은 추가하지 않는다.
- callback은 권위 조회·동일 거래 검증을 거쳐 관찰을 먼저 저장하고 공통 업무 반영 경계를 사용한다. 수동 대사는 이미 저장된 검증 종결 결과를 재적용하거나 기존 거래를 조회·검증·저장한 뒤 같은 경계를 사용한다.
- 신규 PG 결제에서 포인트를 차감하지 않고 과거 POINT 기록·재확정 오류는 보존한다.
- 재고 차감·복구 기록은 mall의 별도 모델이다. 확정 실패의 결과 반영 TX에서 실제 재고와 복구 기록을 함께 갱신한다.
- A와 후속 보완: 조율 파사드와 준비/검증 결과 저장/공통 업무 반영 TX 컴포넌트를 분리한다. 관찰 먼저 commit 뒤 업무를 반영한다. PG HTTP는 TX 밖이며 callback·수동 대사·자동 재확인은 공통 반영 진입점을 사용한다.
- 수동 대사는 현재 실행 ID·상태·회차를 조건으로 새 ID를 기록하고 옛 실행의 진행 save를 차단한다. READY claim과 RUNNING/MANUAL_REQUIRED 인계를 구현했다. 자동 lease는 도입하지 않는다.
- 고객 confirm/상세/reconcile은 기존 X-USER-ID로 저장된 주문 소유자를 비교한다. 과거 POINT 고객 상세도 포함하며 실제 로그인·Spring Security는 도입하지 않는다.
- 타인 주문은 없는 주문과 같은 404·ORDER_NOT_FOUND·메시지로 응답하며 상태·결제 결과·키 충돌 정보를 먼저 노출하지 않는다.
- 주문 관리자 조회·미완료 목록·운영자 대사는 기존 1번 관리자 fixture를 확인한다. 고객 API는 1번도 본인 주문만 처리하며, 상품 등 다른 관리자 API는 이번 변경 범위에서 제외한다.

소유권은 기존 정책과 원문의 차이였으며 승인 범위는 고객/주문 관련 관리자 API다. 실제 인증 체계나 다른 관리자 API까지 확장하지 않았다.
정확한 DTO·잠금 순서·충돌 기록·오류 코드·클래스 배치는 구현 계획에 반영했다. 개별 문서의 당시 미정 항목도 현재 계약은 계획·결과를 우선한다.
