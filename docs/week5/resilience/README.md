# 결제 장애 대응 문서 읽기

이 폴더는 **현재 구현이 결제 중복·동시 실행·PG 조회 장애에 어떻게 대응하는지** 설명한다. 처음 읽는 개발자가 개념→사례→코드 순서로 이해할 수 있도록 작성했다. 논의 중 철회한 대안은 기존 `trade_off/`에 보존한다.

PG는 결제를 처리하는 별도 서버이며 여기서는 직접 만든 학습용 서버를 뜻한다. TX(트랜잭션)는 여러 DB 변경을 함께 확정 저장(commit)하거나 함께 취소(rollback)하는 묶음이다.

## 먼저 기억할 규칙

재고 5개 중 2개를 주문하면 PG 호출 전에 재고를 3개로 줄여 저장한다. 결제 성공이면 3개를 유지하고, 확정 실패이면 5개로 한 번 복구한다. 응답을 못 받았거나 결과가 처리 중이면 3개를 유지한다.

PG가 성공한 뒤 응답만 유실될 수 있다. 따라서 timeout·회로 차단·조회 한도 소진은 결제 실패를 증명하지 않는다.

| 4 | [서킷브레이커](circuit-breaker.md) | 어떤 조회를 집계하고 언제 차단·탐색·회복하는가? |
| 5 | [재시도 전략](retry.md) | PG 조회와 내부 반영을 각각 어떤 조건·한도로 다시 수행하는가? |
| 6 | [폴백 전략](fallback.md) | 조회하지 못했을 때 무엇을 반환하고 어떻게 마무리하는가? |

주문 상태와 재고 기록 자체가 궁금하면 [주문 상태](../states/order.md)와 [재고 상태](../states/stock.md)를 이어 읽는다. 상태 전이 정의는 기존 문서를 기준으로 하고 이 폴더에서 중복 정의하지 않는다.

## 비슷해 보이지만 답하는 질문이 다르다

| 장치·기록 | 답하는 질문 | 이 구현의 예 |
|---|---|---|
| 요청 키·DB 유일 제약 | 같은 결제 요청을 이미 접수했는가? | 전역 유일 키·주문당 한 시도 |
| 주문 상태 CAS | 준비·결과 반영을 내가 맡아도 되는가? | 예상 상태일 때만 변경하고 재고·기록을 같은 TX로 반영 |
| 복구 실행 ID | 현재 진행을 맡은 실행이 맞는가? | 인계 전 실행의 늦은 회차·사유 갱신 차단 |
| HTTP timeout | 한 번의 통신을 얼마나 기다릴 것인가? | 연결 1초·연결 풀 대기 1초·응답 대기 2초 |
| 조회 Retry | 기존 거래를 다시 확인해도 되는가? | 자동 조회 최대 4회·1/3/10초±20% |
| 내부 반영 Retry | 저장된 결과의 업무 TX를 다시 수행해도 되는가? | 전체 rollback이 확인된 MySQL 데드락만 100ms 뒤 추가 1회 |
| CircuitBreaker | 지금 PG 조회를 허용할 것인가? | 여러 주문이 공유하는 `pg-lookup` 회로 |
| fallback | 조회가 차단되거나 자동 확인을 끝내면 어떻게 대응할 것인가? | 확인 불가 사유를 남기고 저장 결과·차감 재고 유지 |
| 결제 결과 | PG의 결과를 무엇으로 확인했는가? | UNKNOWN·PENDING·SUCCESS·FAILED |
| 복구 진행 | 우리 주문·재고 반영은 끝났는가? | READY·RUNNING·MANUAL_REQUIRED·APPLIED |

HTTP 제한들은 대기 단계별 값이다. 자동 조회의 30초 예산은 큐·조회·재시도 대기를 포함하며, 이미 시작한 HTTP와 결과 저장을 강제로 취소하는 시간은 아니다.

## 한 가지 사례로 연결하기

1. PG가 거래를 접수해 PENDING을 알려 줬다. 우리 주문은 PAYMENT_PENDING, 재고는 3개다.
2. 자동 조회의 회차 1을 DB에 저장했지만 공유 회로가 OPEN이라 PG HTTP를 보내지 못했다.
3. 폴백은 CIRCUIT_BLOCKED를 반환한다. 자동 작업은 MANUAL_REQUIRED가 되지만 PG 결과는 PENDING, 재고는 3개를 유지한다.
4. 회로 회복 뒤 담당자가 명시적 대사를 요청한다. 같은 거래의 SUCCESS를 확인하면 먼저 사실을 저장하고 별도 업무 TX로 주문을 확정한다. 재고는 3개이며 추가 결제도 없다.

회로 상태는 여러 주문의 조회 상태이고 결제 상태는 특정 주문의 사실이다. OPEN·MANUAL_REQUIRED를 FAILED와 같은 뜻으로 읽지 않는 것이 출발점이다.
