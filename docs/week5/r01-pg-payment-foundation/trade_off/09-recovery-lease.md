# 복구 작업 실행 권한의 만료·회수

[설계 질문 목록](total_trade_off.md) · [실행 권한 결정](08-recovery-claim-coordination.md) · [재확인 예산](../../r03-payment-resilience/trade_off/01-reconciliation-retry-policy.md)

상태: **사용자 요청으로 보류·A/B 미채택·구현 전**. 만료 시간·갱신 주기·구체적인 필드는 정하지 않는다.
후속 [최소 보완](10-learning-scope-completion.md)에서 자동 lease/회수는 현재 범위에서 도입하지 않고 수동 실행 ID 교체로 인계하기로 확정했다. commerce의 지터·다음 실행 예약 정보도 저장하지 않는다. 아래 A/B 비교의 만료/재개 예약은 채택한 요구사항이 아니다.

## 후속 사용자 결정

2026-10-21 사용자는 자동 만료/회수 논의를 넘기고 운영 담당자가 장애로 중단된 작업까지 조회해 수동 대사하는 방식을 선택했다.
정상 실행의 @Retryable 최초+추가 3회는 유지한다. 중단 작업의 commerce 재시작 자동 재개는 운영 담당자의 수동 대사로 변경한다.
아래 A/B는 비교 기록으로 보존하며 어느 안도 현재 구현 대상으로 채택하지 않았다.
현재 정책은 R02의 [미완료 작업 조회·운영 담당자 수동 대사](../../r02-pg-order-payment/trade_off/06-interrupted-payment-reconcile.md)를 따른다.

## 판단할 문제

실행 권한을 DB에 기록한 뒤 TX를 종료한다. 따라서 프로세스가 종료돼도 DB의 실행 중 기록은 남을 수 있다.
다른 실행이 그 작업을 언제 이어받을 수 있는지 기준이 필요하다. 실행 권한 회수는 PG 결제 생성 재발송을 뜻하지 않는다.
아래는 재시도 흐름을 맡은 실행의 권한에 만료를 두는 두 안이다. 구체적인 점유 단위와 필드/시간은 후속 설계에서 정한다.

## A. 시작할 때 정한 만료 시각 유지 · 이전 추천·보류

- 실행 권한을 확보할 때 만료 시각을 정하고 자동 연장하지 않는다.
- 다른 실행은 유효한 권한을 존중하고, 만료 뒤 권한 확보 TX에서 미완료 여부·남은 예산을 확인해 새 실행 권한을 확보한다.
- 이득: 갱신 작업 없이 종료된 실행의 권한을 회수할 수 있고 시간 기준을 추적하기 쉽다.
- 비용: 서버가 일찍 종료돼도 만료까지 기다릴 수 있다. 정상 실행이 예상보다 길어지면 권한이 만료될 수 있다.
- 만료 길이는 전체 재확인 시간 예산을 기준으로 정한다. 확정한 대기 합만 최대 16.8초이며 HTTP·DB·실행기 대기도 포함해야 한다. 아직 초 단위 수치는 정하지 않았다.

## B. 정상 실행 중 만료 시각 갱신 · 보류

- 실행 권한에 만료를 두고 정상 실행이 계속되는 동안 주기적으로 연장한다.
- 갱신이 중단되고 만료 시간이 지나면 다른 실행이 같은 DB 보호 경계에서 회수할 수 있다.
- 이득: 실행 시간이 달라져도 진행 중인 작업의 권한을 유지하기 쉽다.
- 비용: 갱신 주기·DB 쓰기·갱신 실패·정지된 실행과 회수 실행의 경합을 추가로 다뤄야 한다.
- 갱신이 된다는 이유로 재조회 횟수나 전체 시간 예산을 늘리지 않는다.

## 두 안의 공통 조건·남은 질문

- 만료 뒤 재개해도 조회 직전 commit한 사용 횟수는 취소하지 않는다. 최초+추가 3회 예산을 다시 부여하지 않는다.
- 만료된 예전 실행이 뒤늦게 돌아와 새 실행의 진행을 덮어쓰지 못하도록 실행 식별자/세대 등 검증이 필요하다. 구체적인 형식은 미정이다.
- 실행 권한 상실 후 새 조회 회차를 시작하지 못하게 하고, 이미 진행 중이던 조회의 늦은 결과 처리와 공통 결과 반영 TX의 보호 규칙을 설계한다.
- 권한 회수만으로 외부 조회의 완전한 비중첩이나 업무 반영 한 번을 보장하지 않는다. 주문 확정·재고 복구의 멱등성은 공통 결과 반영 TX에서 보호한다.
- 수동 전환·반영 완료한 작업은 자동 회수로 다시 활성화하지 않는다. 검증된 callback·수동 대사 경계는 기존 결정을 따른다.
- 재시작 시 아직 만료되지 않은 작업의 재개 예약·남은 대기 보존·DB 시간 기준·동시 회수의 잠금 순서는 후속 질문이다. 상시 DB 대상 탐색 스케줄러를 새로 채택한 것은 아니다.

이전에는 제한된 재시도 흐름에 A를 추천했지만 사용자는 자동 회수 대신 운영 담당자 수동 대사를 선택했다.
자동 회수를 다시 범위에 넣을 때 이 비교와 시간 예산을 재검토한다. 이번에는 특정 만료 설정값을 확정하지 않는다.
