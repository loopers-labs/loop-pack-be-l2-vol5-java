## 결과를 구분하는 방식

adapter는 검증한 거래, 생성 전 효과 0건 확정 거절, 거래 미조회, 통신/응답 확인 불가, 식별 충돌을 구분한다.
timeout·빈 조회·HTTP 오류를 결제 FAILED로 바꾸지 않는다. 403과 503은 숫자 상태 코드로 구별하고 응답 원문은 저장하지 않는다.
주문·금액·거래 키·상태의 타입과 값을 검사하며 정상 JSON 뒤에 다른 JSON이나 잘못된 내용이 붙어도 거절한다.

PG 호출은 관찰 저장 TX 밖에서 끝난다. 확인한 성공·실패·거절 사실을 먼저 commit하므로 후속 업무 TX가 rollback돼도 근거는 남는다.
동시 PENDING/SUCCESS 관찰은 SUCCESS를 보존하고, SUCCESS/FAILED 관찰은 먼저 저장된 종결 사실과 상충 표시를 함께 남긴다.
이 행 잠금은 관찰 저장용이며 복구 작업의 실행 권한은 기존 CAS 방식을 유지한다.

전체 검사는 다음 명령으로 실행했다.

```powershell
./gradlew.bat :apps:test-pg:check :apps:commerce-api:check --offline --console=plain --init-script build/docker-api.init.gradle
```

로컬 Docker API 호환 때문에 무시 대상 임시 init script로 테스트 JVM에 `api.version=1.44`를 지정했다.
검사 기준이나 추적 대상 공통 설정은 완화하지 않았다. 전체 검사 뒤의 변경은 승인된 payment-lab 포트·로그 설정이며,
해당 변경은 JAR 재빌드와 기본 포트의 실제 웹 동시 기동으로 추가 검증했다. 같은 전체 검사를 반복하지 않았다.

검증 로그·Gradle XML 결과·프로세스 실험 출력은 로컬 `build/` 아래에 있다. 재현 방법과 실험용 `PaymentLabProbe.java`는
[실행 문서](../../../docker/payment-lab/README.md)에 남겼다. 실험용 서버와 전용 DB는 확인 후 정지하며 기존 MySQL·Redis는 보존한다.

## 리뷰에서 승인받아 보완한 사항

기능 커밋 전에 비즈니스·사용자 경험·기술 관점 리뷰를 받았다. 중요한 보완은 사용자에게 구체안을 확인받고 수정·관련 검사·세 관점 재리뷰를 진행했다.

- PG 입력에서 문자열/소수를 정수로 자동 변환하거나 알 수 없는 테스트 옵션을 무시하지 않도록 PG 전용 JSON 검증을 강화했다.
- 동시 관찰의 유실을 막는 짧은 행 잠금, HTTP 오류 코드 보존, adapter 전용 JSON 끝 토큰 검사를 적용했다. `8f40965`에 포함했다.
- 실제 웹 동시 기동에서 발견한 관리 포트 충돌과 콘솔 누락을 payment-lab에 한정해 수정했다. `f3931d5`에 포함했다.

최종 재리뷰에서 미해결 중요 지적은 없었다. 문서·테스트만 바뀌는 정리는 별도 기능 리뷰 대상으로 확대하지 않았다.
