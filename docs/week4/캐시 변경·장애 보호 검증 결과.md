# 캐시 변경·장애 보호 검증 결과

2026-10-15, 로컬 실제 MySQL·Redis Testcontainers 기준.

## 추가한 검증: 캐시 경로 비교·늦은 채움 보호

**빠져 있던 테스트 10개를 추가했다.** 같은 데이터에서 DB-only·miss·hit을 비교하는 6개와, 늦은 채움 중 사용자·주문을 보호하는 4개다. 기존 기대값·운영 코드·좋아요 TTL 정책은 변경하지 않았다.

### DB-only·miss·hit 비교

정렬 3종 × 브랜드 필터 유무, 각 조건의 page=0/1/2·size=2에서 같은 HTTP 요청을 세 번 실행한다. 첫·다음·빈 페이지, 가격/좋아요 동점, 좋아요 0개, 삭제 상품을 포함한다.


| 경로      | 응답·캐시 확인                             | 원본 목록 조회 |
| ------- | ------------------------------------ | -------- |
| DB-only | 캐시 비활성 분기 사용, Redis 키 미생성            | 1회       |
| miss    | DB-only와 전체 JSON 일치, Redis 저장·TTL 확인 | 1회       |
| hit     | DB-only·miss와 전체 JSON 일치             | 0회       |


DB-only에서는 테스트 spy로 활성화 판단만 false로 바꾸고 실제 비활성 분기를 실행한다. DB·Redis·응답은 실제 경로를 사용하며 데이터는 세 조회 사이에 바꾸지 않는다. 별도 OFF 프로필 재기동 검증은 아니다. 원본 목록 조회는 `findBasicPage` 호출 수이며, 인증·revision SQL은 hit에도 남는다.

### 늦은 채움에서도 보호하는 조건

실제 DB 읽기 완료 → latch로 정지 → 기존 API로 변경 commit → 옛 읽기 재개·옛 키 저장 순서를 강제한다. 옛 값이 Redis에 실제 남아 있어도 아래 결과를 만족해야 한다.

| 시나리오 | 확인한 결과 |
| --- | --- |
| Alice의 옛 좋아요 목록 저장 | 저장 전후 Bob의 Alice 목록·주문 조회/확정과 미인증 요청 거절. 주문·재고·잔액 유지. Bob 목록 유지, Alice 새 조회는 취소 반영 |
| 옛 가격 100원 저장 | 새 가격 400원으로 주문 생성. 이후 표시 가격 900원으로 바뀌어도 주문 단가 400원 결제. 포인트 부족은 거절하고 상태 유지 |
| 옛 재고 있음 저장 | 새 품절 조회는 true. 주문 확정은 실제 재고 0으로 거절하고 주문·잔액 유지 |
| 삭제 전 상품 상세 저장 | 새 조회 404, 새 주문 생성·기존 주문 확정 거절. 기존 주문 내용·재고·잔액 유지 |

모든 worker는 finally에서 해제·종료하고 유한 시간 내 종료를 확인한다. 기존 관리자 변경·롤백·삭제 시나리오도 유지한다.

관련 검사 **48개 성공**(캐시 44개 + 비동기 로그 4개), 실패·오류·skip 0. 추가 10개 모두 통과, Checkstyle 통과. [관련 실행 결과](experiments/21-cache-path-validation/gap-focused-results.json)

좋아요 숫자·순위는 [현재 API 계약](../week2/api-contract.md)의 TTL 지연 정책을 유지한다. 내 좋아요 목록·삭제 비노출·소유권·주문 판단은 이 지연 대상이 아니다.

## 변경·장애·복구 보호 조건

| 검증 항목 | 결과 |
| --- | --- |
| 관리자 수정·삭제 | 새 값 반영, 삭제 상품 비노출 |
| DB 변경 롤백 | DB 값·revision·기존 캐시 유지 |
| 늦게 끝난 옛 조회 | 옛 revision 키에만 저장, 이후 새 요청에서 사용하지 않음 |
| Redis 장애 중 수정·삭제 후 복구 | DB 우회, 옛 키 무시, 현재 값 재채움 |
| 타인 좋아요·주문 접근 | 장애·복구 모두 조회/주문 확정 거절, 본인 목록·포인트만 반환 |
| 주문 금액·재고·포인트 | 장애·복구 모두 DB 가격으로 주문 생성, 이후 가격 변경에도 주문 저장 단가로 결제. 실제 재고·잔액 차감 |
| 재고·포인트 부족 | 각각 확정 거절, DRAFT·재고·잔액 유지 |
| 브랜드 삭제 | 장애·복구 모두 소속 상품 비노출·새 주문 거절, 다른 브랜드·과거 주문·결제액 유지 |

실제 Redis 중단·복구 시나리오와 정상 관리자 변경·롤백 테스트로 확인했다. 실제 장애의 응답 시간·재연결·재채움 결과는 [Redis 장애 복구 검증 결과](Redis%20장애%20복구%20검증%20결과.md)를 참고한다.
