# R02 구현 계획

## 제출 시 결정 갱신

제출 시 사용자는 Caffeine 로컬 캐시를 이번 구현의 최종 선택으로 확정했다. Redis는 이번에 도입하지 않는다.
아래 승인 범위와 실행 순서는 당시 계획 기록으로 보존한다.
현재 선택의 근거와 한계는 [설계 판단](trade_off/01-local-cache-boundary.md)과 [실제 결과](result.md)에 기록한다.

## 승인 범위와 출발점

2026-10-16 사용자가 승인한 Caffeine 상품 상세 로컬 캐시 계획을 실행한다.
`origin/volume-4/main`의 PR #22 병합 커밋 `3786c0d1b4518a66fa2196586d998a4f09a573ea`에서
`volume-4/r02-product-detail-local-cache`를 생성했다. 사용자 GUI JMX 수정은 별도로 보존한다.

## 커밋과 검증 순서

1. `docs: 상품 상세 Caffeine 캐시 요구사항과 구현 계획 정리`
   - 요구사항·설계 판단·TDD 순서·측정 조건을 먼저 기록한다.
2. `feat: 상품 상세 Caffeine 로컬 캐시와 조회 경계 추가`
   - 캐시 단위·설정 테스트를 먼저 작성하고 Red를 확인한다.
   - Caffeine 의존·설정·세대 보호 캐시·비TX QueryDao 데코레이터·지표를 구현한다.
   - fake 시간원, 용량 유지보수, 예외·미존재·기존 TX 우회와 늦은 채움을 검증한다.
3. `feat: 상품 상세 영향 쓰기의 commit 후 캐시 무효화 연결`
   - 상품·브랜드·집계·주문 재고 이벤트와 동기 AFTER_COMMIT 리스너를 연결한다.
   - 관련 단위·실제 MySQL 통합 테스트를 보완한다. 관계 이벤트와 집계 이벤트를 모두 검증한다.
   - HTTP 실제 SQL 수, 400/404, 전체 응답 일치와 모듈 check를 확인한다.
4. `feat: 상품 상세 캐시 OFF ON 재현 측정 도구 준비`
   - 재현 JMX·PowerShell 실행기와 가이드를 준비한다.
   - 실제 실행 전 도구를 별도 커밋해 입력 해시와 재현 기준을 고정한다.
5. `feat: 상품 상세 측정 결과 요약과 원본 검증 도구 추가`
   - 부하 실행과 독립된 파일 전용 요약기로 JTL·HTML 통계·Prometheus·입력 해시를 검산한다.
   - SQL이 0회인 요청도 빈 SQL 증거 파일을 보존한다. 측정 입력 6개는 변경하지 않는다.
6. `test: 좋아요 증감 집계 롤백의 상세 캐시 보존 검증`
   - 최종 검토에서 확인한 delta flush 사후 rollback의 DB·캐시 경계를 실제 MySQL 사례로 보완한다.
   - 관련 통합 테스트를 먼저 확인하고 최종 전체 check를 다시 실행한다. 운영 구현·측정 JAR는 변경하지 않는다.
7. `docs: 상품 상세 캐시 전후 JMeter 측정과 검증 결과 기록`
   - 같은 새 JAR로 OFF/ON 8개 CLI 본 측정과 8개 워밍업을 실행한다.
   - 데이터·인덱스·설정·API 보존, SQL·캐시 통계와 JTL/HTML 결과를 확인해 원본·요약·해시를 기록한다.

## 실행 경계

- 단위 테스트와 관련 테스트의 Red/Green 로그는 `build/benchmark/r02/`에 보존한다. Gradle은 한 번에 하나만 실행한다.
- 실제 쓰기·rollback·경쟁 테스트는 Testcontainers MySQL에서만 수행한다. 현재 실험 DB는 읽기 측정에만 사용한다.
- 기본 상세 캐시는 OFF다. 전용 통합 테스트와 OFF/ON 실행 인자에서 명시적으로 활성화한다.
- 현재 100만 DB의 seed·스키마·인덱스·서버 설정은 다시 실행하거나 변경하지 않는다.
- 측정은 전용 API 18081/관리 18082를 사용한다. 포트가 사용 중이면 임의 중단하지 않고 충돌을 보고한다.
- 실행기가 생성한 API만 PID·시작 시각·명령행 확인 후 종료한다. 기존 API는 유지한다.
- 측정 앱은 DDL none, seed false, 좋아요 집계 false, COUNT TTL 0s, Redis health false와 기존 timeout을 사용한다.
