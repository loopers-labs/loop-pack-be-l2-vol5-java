# Week 10 제출 체크리스트

상태는 구현 및 실행 증거를 확인한 뒤 갱신한다. 계획·파일 존재만으로 완료하지 않는다.

## 관측과 진단

- [ ] 실제 health·업무 지표·식별자별 경계 기록으로 증상을 설명한다.
- [ ] 최소 두 가설의 예상과 실제를 비교하고 부족한 증거도 표시한다.
- [ ] 비밀값·개인정보를 남기지 않고 metric label의 무한 증가를 피한다.

## 동일 업무 복구

- [ ] 같은 DB·PG 거래 상태를 유지해 baseline→fault→recovery를 이어 간다.
- [ ] 장애 집합은 7·UNKNOWN 3·PG 성공 10이며 같은 집합을 10·0·10으로 복구한다.
- [ ] create 추가 0, 예약·재고·포인트·쿠폰 불변 조건과 중복 적용 방지를 확인한다.
- [ ] 복구 주문의 실제 Outbox·Kafka·구매 활동·주간 랭킹 API를 연결한다.

## 증거와 종료

- [ ] fault 원문을 보존하고 runbook에 중단·재진입 조건을 남긴다.
- [ ] 관련 누적 회귀·lint·ArchUnit 결과와 미검증 위험을 구분한다.
- [ ] 자신이 시작한 테스트 자원만 정리했으며 운영 완료를 주장하지 않는다.

## 기술 글

- [ ] 실제 주문의 장애·복구 상태와 판단을 바꾼 관측을 보여 준다.
- [ ] 선택한 조치와 지킨 불변 조건을 설명한다.
- [ ] 미검증한 범위와 남은 위험을 로컬 실험 결과와 구분한다.
