# Outbox insert 흐름

```text
PG 결과 수신 또는 대사 조회
└─ PaymentGateway.Approved
   └─ OrderPaymentTransactionService.recordResult(orderId, result)
      └─ TXB 시작
         ├─ 결제 성공 기록
         ├─ 재고 예약 소비
         ├─ 주문 CONFIRMED 처리
         ├─ 고정 eventId·messageKey·payload 생성
         ├─ Outbox PENDING insert (eventId UNIQUE)
         └─ commit
            └─ relay가 나중에 Outbox를 읽어 Kafka 발행
```

Outbox insert 실패 시 TXB 전체를 같은 PG 결과로 1회 재시도한다.

## `order_confirmed_outbox`


| 컬럼                | 비고                                                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `id`              | 테이블 내부 식별자                                                                                                                 |
| `event_id`        | 이벤트 식별,멱등키                                                                                                                 |
| `order_id`        | 원본 주문 식별자                                                                                                                  |
| `event_type`      | `OrderConfirmed`                                                                                                           |
| `schema_version`  | Producer 인프라가 `OrderConfirmedEvent`를 `OrderConfirmedV1Schema`로 변환할 때 설정하는 계약 버전(현재 `1`). 이 값을 payload와 Outbox 컬럼에 함께 저장한다. |
| `message_key`     | Kafka record key. 현재는 주문 ID 문자열                                                                                            |
| `payload`         | relay가 kafka에게 보낼 본문. insert 뒤 수정하거나 relay에서 재생성하지 않는다.                                                                    |
| `status`          | `PENDING`, `FAILED`, `BLOCKED`, `PUBLISHED`                                                                                |
| `created_at`      | Outbox 행 생성 시각                                                                                                             |
| `published_at`    | broker 성공 확인 시각. `PUBLISHED`일 때 설정                                                                                         |
| `attempt_count`   | relay가 시작한 Kafka 발행 시도 횟수. TXB 재시도 횟수와는 별개                                                                                 |
| `next_attempt_at` | 다음 발행 시도 가능 시각. 신규 행은 생성 시각으로 설정하고, 실패하면 현재 시각에 폴링 간격을 더해 설정한다. 해당 시각 이후 다음 폴링에서 시도한다.                                     |
| `last_error`      | 마지막 발행 실패의 예외 클래스명.                                                                                                        |


# 단일 relay

```text
Outbox PENDING 저장
└─ next_attempt_at = created_at (즉시 발행 대상)

Relay 실행
└─ 이전 조회·발행 처리가 끝난 뒤 1초 대기 (fixedDelay)
   └─ next_attempt_at ≤ 현재 시각인 PENDING·FAILED를 created_at·id 순으로 조회
      └─ 설정된 묶음 크기만큼 한 건씩 순차 처리
         ├─ 발행 시도 시작: attempt_count 증가·저장
         ├─ 주문 TX 밖에서 저장된 topic·message_key·payload를 Kafka로 전송
         └─ producer future 결과 확인 (broker 확인을 받을 수 있는 acks 설정)
            ├─ 성공
            │  └─ 별도 DB TX에서 PUBLISHED·published_at 저장
            └─ 실패
               ├─ 발행 실패 확인 → FAILED
               └─ 성공·실패를 확정할 수 없음(timeout 등) → PENDING
                  ├─ 최대 시도 횟수 도달 → BLOCKED
                  └─ 시도 횟수 남음
                     └─ 상태 유지·next_attempt_at(현재 시각 + 재시도 간격)·last_error 저장
                        └─ 해당 시각 이후 다음 폴링에서 재시도
```

broker 장애가 회복되면 별도 복구 작업 없이 relay의 기본 폴링이 `PENDING`과 재시도 시각이 지난 `FAILED` 행을 다시 처리한다.

## 발행 결과 변환 경계

Relay가 Kafka 응답이나 Kafka 예외를 직접 해석하지 않도록 발행 포트와 Kafka 어댑터를 둔다. Relay는 플랫폼 중립적인 발행 결과만 받아 Outbox 상태를 갱신한다.

```text
OutboxRelay
└─ OutboxPublisher.publish(message)
   └─ KafkaOutboxPublisher
      ├─ KafkaTemplate.send(topic, key, payload)
      └─ Kafka 응답·예외를 PublishResult로 변환
         └─ OutboxRelay가 결과에 따라 Outbox 상태 갱신
```

`OutboxPublisher`는 애플리케이션이 정의하는 발행 포트이고, `KafkaOutboxPublisher`는 이를 구현하는 Kafka 인프라 어댑터다. 포트의 결과는 `SUCCESS`, `FAILED`, `PENDING`으로 표현한다. `PENDING`은 Kafka가 메시지를 받았는지 확정할 수 없는 결과(timeout 등)를 뜻한다.

| 발행 포트 결과 | 의미 | Relay의 Outbox 처리 |
| --- | --- | --- |
| `SUCCESS` | broker 성공 응답 확인 | `PUBLISHED`와 `published_at` 저장 |
| `FAILED` | 발행 실패 확인 | `FAILED`로 기록하고 재시도 대상으로 둠 |
| `PENDING` | 성공·실패를 확정할 응답을 받지 못함 | `PENDING`으로 두고 재시도 대상으로 둠 |

Kafka 어댑터만 `KafkaTemplate`과 Kafka 예외 타입에 의존한다. 어댑터는 실패 결과에 예외 클래스명을 함께 반환할 수 있고, Relay가 이를 `last_error`에 기록한다. Outbox 상태 변경은 Relay 한 곳에서 수행하며 Kafka callback이 상태를 직접 변경하지 않는다. 발행 결과를 어떤 Kafka 응답·예외에서 `FAILED`와 `PENDING`으로 나눌지는 어댑터 정책으로 정한다.


| 설정 항목    | 예시 설정 키                      | 의미                                                | 값       |
| -------- | ---------------------------- | ------------------------------------------------- | ------- |
| 폴링 간격    | `outbox.relay.poll-interval` | 한 번의 조회·발행 처리가 끝난 뒤 다음 실행까지 기다리는 시간(`fixedDelay`) | 기본 `1초` |
| 조회 묶음 크기 | `outbox.relay.batch-size`    | 한 번의 실행에서 순차 처리할 최대 Outbox 행 수                    | 기본 `10` |
| 최대 시도 횟수 | `outbox.relay.max-attempts`  | 발행 결과가 성공으로 확정되지 않은 행을 `BLOCKED`로 전환하기까지 허용할 전체 발행 시도 횟수 | 기본 `3` |
