# Outbox insert 흐름

```text
PG 결과 수신 또는 대사 조회
└─ PaymentGateway.Approved
   └─ OrderPaymentTransactionService.recordResult(orderId, result)
      └─ TXB 시작
         ├─ 결제 성공 기록
         ├─ 재고 예약 소비
         ├─ 주문 CONFIRMED 처리
         ├─ 고정 eventId·messageKey·payload 생성
         ├─ Outbox PENDING insert (eventId UNIQUE)
         └─ commit
            └─ relay가 나중에 Outbox를 읽어 Kafka 발행
```

## Outbox insert 실패 후 대사 복구 흐름

Outbox insert가 실패하면 예외가 전파되어 TXB 전체가 롤백된다.

이후 주기적으로 실행되는 대사 작업에서 기존 `paymentKey`로 PG 결과를 조회해 재시도한다.

최초 PG 승인 응답을 처리할 때와 대사로 승인 결과를 확인했을 때 모두 `OrderPaymentTransactionService.recordResult()`를 호출한다.

주문·결제·재고 예약·Outbox 저장을 수행하는 TXB 로직은 이 공통 경로에서 처리한다.

```text
Outbox PENDING insert 실패
└─ 예외 전파 → TXB rollback
   ├─ DB: 주문 DRAFT·결제 PENDING·예약 RESERVED 유지, Outbox 없음
   └─ PG: 이미 완료된 승인은 그대로 유지
      └─ 다음 대사 주기
         └─ PendingPaymentRecoveryService가 기존 paymentKey로 PG 조회
            ├─ 승인 확인
            │  └─ OrderPaymentTransactionService.recordResult()
            │     └─ 공통 TXB 경로 재수행 → Outbox 저장 시도
            └─ 결과 미확정 또는 조회 실패
               └─ 현재 상태 유지 → 다음 대사 주기에 다시 조회
```



## `order_confirmed_outbox`


| 컬럼                | 비고                                                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `id`              | 테이블 내부 식별자                                                                                                                 |
| `event_id`        | 이벤트 식별,멱등키                                                                                                                 |
| `order_id`        | 원본 주문 식별자                                                                                                                  |
| `event_type`      | `OrderConfirmed`                                                                                                           |
| `schema_version`  | Producer 인프라가 `OrderConfirmedEvent`를 `OrderConfirmedV1Schema`로 변환할 때 설정하는 계약 버전(현재 `1`). 이 값을 payload와 Outbox 컬럼에 함께 저장한다. |
| `message_key`     | Kafka record key. 현재는 주문 ID 문자열                                                                                            |
| `payload`         | relay가 kafka에게 보낼 본문. insert 뒤 수정하거나 relay에서 재생성하지 않는다.                                                                    |
| `status`          | `PENDING`, `FAILED`, `BLOCKED`, `PUBLISHED`                                                                                |
| `created_at`      | Outbox 행 생성 시각                                                                                                             |
| `published_at`    | broker 성공 확인 시각. `PUBLISHED`일 때 설정                                                                                         |
| `attempt_count`   | relay가 시작한 Kafka 발행 시도 횟수. TXB 재시도 횟수와는 별개                                                                                 |
| `next_attempt_at` | 다음 발행 시도 가능 시각. 신규 행은 생성 시각으로 설정하고, 실패하면 현재 시각에 재시도 간격을 더해 설정한다. 해당 시각 이후 다음 폴링에서 시도한다.                                    |
| `last_error`      | 마지막 발행 실패의 예외 클래스명.                                                                                                        |
