# 이벤트 계약 관리 구조

```text
event-contracts/                                  # 서비스 공통 이벤트 계약
└── schemas/
    ├── order-confirmed.v1.schema.json            # 주문 확정 이벤트 계약
    └── order-cancelled.v1.schema.json            # 취소 이벤트 계약

apps/
├── commerce-api/                                 # 주문 이벤트 발행 서비스
│   ├── src/main/resources/application.yml        # 이 서비스의 Kafka 설정
│   └── src/main/java/com/loopers/order/
│       ├── application/event/                    # 비즈니스 이벤트
│       └── infrastructure/kafka/                 # Kafka producer·발행 어댑터
└── commerce-streamer/                             # 주문 이벤트 소비 서비스
    ├── src/main/resources/application.yml        # 이 서비스의 Kafka 설정
    └── src/main/java/com/loopers/purchase/
        ├── application/                          # 이벤트를 업무에 적용
        └── infrastructure/kafka/                 # Kafka consumer·수신 어댑터

docker/
└── infra-compose.yml                             # 로컬 Kafka broker 실행 환경
```

## 스키마와 서비스 DTO

- Consumer는 업무에 필요한 DTO를 정한다. 이 DTO는 이벤트 스키마 버전과 무관하다.
- Consumer 인프라는 버전별 JSON Schema로 이벤트를 검증하고, 필요한 필드와 의미가 DTO에 호환되는지 확인해 변환한다.
- 호환되면 업무 처리로 넘기고, 호환되지 않으면 거부해 ack하지 않는다.



## Kafka record와 이벤트 payload

```text
Kafka record
├── key: "42"                 # Kafka가 사용하는 키 (orderId를 문자열로 표현)
└── value:                     # 실제 이벤트 JSON
    ├── eventType: "OrderConfirmed"
    ├── schemaVersion: 1
    ├── eventId: "order-confirmed:42"
    ├── orderId: 42
    ├── confirmedAt: "2026-09-07T01:00:00Z"
    └── items: [...]
```
