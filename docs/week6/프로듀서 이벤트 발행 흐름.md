# 프로듀서 경계 분리

## 목표

> 비즈니스 코드는 `OrderConfirmed` 이벤트를 발행한다는 사실만 알고, Kafka 토픽과 전송 방식은 Kafka 인프라가 담당한다.

## 현재 프로듀서 흐름

```text
결제 승인
└─ OrderPaymentTransactionService.recordResult() [application]
   ├─ 주문 상태 저장
   └─ eventPublisher.publishEvent(OrderConfirmedEvent.from(order))
      └─ DB 트랜잭션 commit 후
         └─ OrderConfirmedKafkaPublisher.publish() [Kafka infrastructure]
            ├─ OrderConfirmedEvent → OrderConfirmedV1Schema 변환
            ├─ 설정에서 topic 조회: order-events
            ├─ KafkaTemplate.send(topic, orderId, message)
            └─ 전송 결과 비동기 로그
```

| 단계 | 계층·객체 | 하는 일 |
| --- | --- | --- |
| 업무 이벤트 발행 | `OrderPaymentTransactionService.recordResult()` | 결제 승인 후 주문 상태를 저장하고 `OrderConfirmedEvent`를 Spring 이벤트로 발행한다. |
| DB commit 이후 처리 | `OrderConfirmedKafkaPublisher.publish()` | `@TransactionalEventListener(phase = AFTER_COMMIT)`으로 주문 트랜잭션이 commit된 다음 실행된다. |
| 계약 메시지 변환 | `OrderConfirmedKafkaPublisher` | 애플리케이션 이벤트를 공통 JSON Schema에서 생성한 `OrderConfirmedV1Schema`로 변환한다. |
| Kafka 전송 | `KafkaTemplate.send()` | Publisher가 설정에서 topic을 읽고, 주문 ID 문자열을 record key로 사용해 메시지를 전송한다. |
| 전송 결과 기록 | `OrderConfirmedKafkaPublisher.logResult()` | 비동기 전송의 성공 시 topic·partition·offset을, 실패 시 오류를 로그로 기록한다. |

토픽 설정은 `apps/commerce-api/src/main/resources/application.yml`의 `order-confirmed.kafka.topic`에 있다. 현재 Publisher는 전송 결과를 기다리지 않고, 실패를 로그로 기록한다.
