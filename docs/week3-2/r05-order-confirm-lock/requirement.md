# R05. 주문 확정 잠금 조회 개선

[전체 요구사항](../total_requirement.md) · 작업 브랜치: `volume-3/r05-order-confirm-lock` · PR 대상: `volume-3/main`

상태: 문서 준비. 트레이드오프 문답 전이며 채택안은 없다. R04 병합 후 시작한다.
기준 항목: 분석 항목 3(상품별 개별 잠금 조회와 저장 시 재조회).

## 1. 목적

주문 확정 트랜잭션의 DB 왕복 수를 줄여 잠금을 쥐고 있는 시간을 줄인다.
R02에서 보장한 원자성·경쟁 제어·잠금 순서는 그대로 유지한다.

## 2. 현재 동작과 변경점

| 구분 | 현재 코드에서 확인한 동작 | 요구하는 변경 |
|---|---|---|
| 잠금 조회 | `infrastructure/dao/ordering/JpaConfirmOrderWriter.load`가 주문 → 지갑 → 상품 ID 오름차순으로 상품마다 `ProductJpaRepository.findByIdForUpdate` 1회씩 실행 | 상품 N개의 잠금 조회 횟수 감소. 잠금 순서 유지 |
| 저장 | `JpaConfirmOrderWriter.save`가 상품마다 `productRepository.save`(내부 `findById` + flush), 지갑·사용 기록·주문 저장 | 이미 잠가 읽은 행을 다시 조회하지 않도록 개선 |
| 업무 판단 | `OrderConfirmationPolicy.confirm`이 도메인에서 재고·잔액·상태 판단 | 유지(대안 비교 결과에 따라 변경 시 사용자 합의) |

## 3. 포함·제외 범위

**포함**

- 주문 확정의 잠금 조회·저장 쿼리 수 감소.
- R02 동시성 테스트(재고 경쟁·포인트 경쟁·동일 주문 동시 확정·관리자 재고 설정)의 회귀 확인.
- 변경 전후 요청당 쿼리 수 비교.

**제외**

- 주문 생성, 충전, 관리자 재고 설정 경로의 잠금 방식 변경(회귀 확인만 수행).
- repository 공통 저장 구조 변경(R06).
- 비관적 잠금 외 전략의 추가 구현·비교 실험. 조건부 UPDATE는 문서상 대안 비교만 한다.

## 4. 규칙

- 잠금 순서는 주문 → 지갑 → 상품 ID 오름차순이다([R02 트레이드오프](../../week3/r02-order-consistency/trade_off/total_trade_off.md)).
- 재고·잔액 부족, 삭제 상품, 이미 확정된 주문의 거절 결과와 오류 코드는 기존과 같다.
- 실패하면 재고·잔액·주문 상태·주문 기록·사용 기록 모두 롤백된다.

## 5. 시나리오와 기대 결과

| 시나리오 | 사전 상태 | 실행 | 기대 결과 | 유지되어야 할 상태 |
|---|---|---|---|---|
| 다품목 확정 | 상품 N개를 담은 DRAFT 주문, 충분한 재고·잔액 | 확정 | 성공, 상품 잠금 조회 횟수가 N회보다 적음 | 확정 결과·금액 |
| 재고 경쟁 | 재고보다 많은 동시 확정 요청 | 동시 확정 | 성공 수 = 재고, 나머지 재고 부족 | R02 경쟁 테스트 기대값 |
| 교차 품목 경쟁 | 서로 다른 순서로 같은 상품들을 담은 주문 | 동시 확정 | 데드락 없이 완료 | 잠금 순서 |
| 중간 실패 | 변경 SQL 실행 후 저장 경계에서 오류 유발 | 확정 | 전체 롤백 | R02 롤백 테스트 기대값 |

## 6. 완료 조건

- 변경 전후 주문 확정 1회의 실행 SQL·쿼리 수를 `result.md`에 기록한다.
- R02 동시성·롤백 테스트(`slowTest` 포함)가 기대값 변경 없이 통과한다.
- `./gradlew :apps:commerce-api:check`가 통과한다.

## 7. 미정 사항

트레이드오프 문답으로 결정한다. 아래는 후보 목록이며 채택을 의미하지 않는다.

- 상품 잠금 조회: `WHERE id IN (…) ORDER BY id FOR UPDATE` 일괄 조회 / 기존 개별 조회 유지.
- 재고 차감: 도메인 판단 유지 / 조건부 UPDATE(`stock >= ?`). R02 [동시성 제어](../../week3/r02-order-consistency/trade_off/02-concurrency-control.md)에서 미채택한 대안을 다시 볼 조건.
- 저장 시 재조회 제거를 이 요구사항에서 할지, R06의 공통 저장 구조 변경에 맡길지.
